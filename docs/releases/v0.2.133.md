## Droppen App for macOS

`Droppen-0.2.133.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.127 to 0.2.132 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to Update*. Droppen 0.2.125 and 0.2.126 update themselves in two steps: first to 0.2.127, which https://github.com/getdroppen/releases (where they look for updates, now archived) still offers, then from 0.2.127 to this release. Version 0.2.124 and older do not update themselves: download this DMG once and replace the app in Applications.

## macOS 版 Droppen App

`Droppen-0.2.133.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

0.2.127 至 0.2.132 会自动更新到这个版本：在后台下载，并在你下次退出时安装；也可以用「重启以更新」立即安装。0.2.125 和 0.2.126 会分两步自动更新：先更新到 0.2.127（它们检查更新的 https://github.com/getdroppen/releases 已归档，但仍提供 0.2.127），再从 0.2.127 更新到这个版本。0.2.124 及更早的版本不会自动更新：请手动下载一次这个 DMG，替换「应用程序」里的 Droppen。

## What's new in v0.2.133

### Updating Droppen

- **An Updates page says what changed, and one control says there is something to do.** The rail's bordered *restart* chip is now a small arrow with the version beside the health dot and the theme toggle: it shows while an update downloads, while one is ready, or when a check failed, and it never restarts Droppen by itself. Clicking it opens `/updates`: the version you are on, its release notes in your language first (the other one a click away), and the one action, restart. Settings → General has one line, such as *Droppen 0.2.132 · up to date ›*, that opens the same page.
- **The page says where an update stands.** Checking, downloading with a percentage, ready, up to date, or what failed, in plain words; a copy that cannot update itself says so. *Later* hides the rail mark until the next version — the update still installs when you next quit — and *check now* sits on the page. When you are up to date it shows what changed in the version you are on.

### The cloud pages

- **Denser, quieter pages.** A 28–32px title, section heads with a small mono index, 14/13/12 text, and space plus one rule per section where boxy hairlines used to be. Cloud content stops at about 1200px.
- **My devices leads with a summary.** The header reads *N devices · N offline · N need you*, and usage leads with one sentence and five numbers that reflow to the container's width. Each device row is a fixed 56px beat — icon, name, status dot and word, one action, then *⋯* — with ids, fingerprints, paths, last seen, renewal and warnings in a disclosure inside the row. Pending and removed devices are compact rows of their own, the removed list is one muted line with a count, and an empty list is one sentence and one action.
- **A wide window turns the device list into cards.** From a 44rem container up, the list becomes a grid of cards (tracks of at least 20rem, 12px gaps); one or two devices stay 20rem wide instead of stretching. Below that the 56px row is unchanged. Hover no longer paints the whole row grey: the card's frame darkens, the name underlines, and the action's border darkens.
- **One checkbox and one switch.** Every checkbox the browser used to draw — on the devices, account, link, renewal, schedule and compatibility screens — is now one 14px ink square (16px where you touch it, a 2px focus ring), and settings uses the same 24×14 switch as the rest of the app. Radio groups keep the browser's own behaviour.
- **Settings and select menus share their measurements.** One settings column at 48rem, a label/control grid from 36rem up, rows of 44px or 56px; selects open the menu sheet's own measurements (a 32px trigger, 40px on phones, the chevron turning, a checked row raised with a check mark), and a 2px ink outline marks focus everywhere. The device picker follows the same rules.
- The hub address shown when you sign a computer in elsewhere is now `https://api.droppen.app`. App, site and download links still use `my.` and `www.`, and the install command is unchanged.

### Moving to api.droppen.app

- **New installs join `wss://api.droppen.app`.** The installer, the local server a new install starts, and the peer probe all default to it; the install command itself is still `https://droppen.app/install.sh`. The apex stays as a temporary machine address so installs enrolled before the move keep working, and any hub you set yourself still wins.
- **Installs enrolled before the move move themselves.** At start an agent that still has the apex in its state makes one pre-flight sign-in to `wss://api.droppen.app` and keeps the new origin only if the canonical hub welcomes the machine, within ten seconds. A hub that cannot be reached, or refuses the machine, leaves the enrolled origin alone, and nothing else changes: same machine, same account, same chain.
- Pages served from Cloudflare now call the machine API on `api.` cross-origin; they used to name relay hosts that do not answer yet, which closed every relay connection a page opened.

### Waking, and relays that stop answering

- **A phone that slept gets its connections back at once.** On waking, a page pings and demands an answer within two seconds: the hub link reconnects immediately, relay and feed sockets whose peer does not answer are replaced, and one that answers is kept. Before, dead sockets looked open and the page could wait up to 25 seconds for the hub and 60 for a relay or feed.
- **A relay path whose peer went quiet no longer sits frozen.** An unanswered probe for two intervals (10 seconds) closes the channel and wakes the carrier, so the next channel opens on a live route, instead of waiting for the 60-second silence with the indicator stuck around *20005 ms*. Probes skipped because the page's timers were held are forgotten rather than aged, so unlocking a phone no longer rebuilds a healthy channel; a Wi-Fi ↔ cellular change now wakes the page like a resume.

### VS Code needs code-server

- **Opening VS Code without code-server says so.** The *+* → *VS Code* on a device without code-server used to fail with a bare 409 shown only as a tooltip on the *+*; the server now checks PATH first and the app opens a dialog: VS Code runs in code-server, which Droppen does not install — install it (for example into `~/.local/bin`), click again, and no restart is needed. The dialog links code-server's install guide, in English, both Chinese scripts and Japanese; the tooltip reads *VS Code needs code-server*. The READMEs list code-server as an optional prerequisite, and note that `~/.local/bin` is on the PATH of the installer's service and the desktop app's server.

## v0.2.133 更新内容

### 更新 Droppen

- **「更新」页会说明改了什么，一个控件告诉你该做什么。** 侧边栏以前那个带边框的「重启」小块，换成了健康点与主题开关旁边的一个小箭头加版本号：更新下载中、已就绪、或检查失败时才出现，而且它自己绝不会重启 Droppen。点它打开 `/updates`：当前版本、这个版本的更新内容（先显示你的语言，另一种点一下就切），以及唯一的动作「重启」。设置 → 通用里多了一行，比如「Droppen 0.2.132 · 已是最新 ›」，点开也是这一页。
- **这一页会说更新到了哪一步。** 检查中、下载中（带百分比）、已就绪、已是最新、或者出了什么问题，都用平常的话写清；自己不能更新的副本也会说明。「以后再说」会隐藏侧边栏的标记，直到下一个版本——更新仍会在你下次退出时安装——「立即检查」就在这一页。已是最新时，它显示当前版本改了什么。

### 云端页面

- **页面更紧凑、更安静。** 标题 28–32px，小节标题带一个小的等宽编号，正文 14/13/12；以前那些方框线换成了留白，每节只有一条分隔线。云端内容宽度停在 1200px 左右。
- **「我的设备」开头就是总结。** 页头写着「N 台设备 · N 台离线 · N 台需要你」，用量一栏先一句话、再五个数字，按容器宽度自动换行。每台设备一行固定 56px：图标、名称、状态点和文字、一个动作，然后是「⋯」；id、指纹、路径、最后在线时间、续期和警告都收在该行内的展开里。待批准和已移除的设备各有自己的紧凑行，已移除列表是一行灰色文字加数量，空列表就是一句话加一个动作。
- **窗口够宽时设备列表变成卡片。** 容器宽于 44rem 时，列表变成卡片网格（每列至少 20rem，间距 12px）；只有一两台设备时仍保持 20rem 宽，不会拉伸。窄于这个宽度时，56px 那一行不变。悬停不再给整行涂灰：卡片边框变深、名称加下划线、动作按钮的边框变深。
- **一个复选框，一个开关。** 设备、账户、链接、续期、计划和兼容性页面上，以前由浏览器自己画的复选框，现在都是同一个 14px 的墨色方块（触摸时 16px，2px 焦点圈）；设置页用的是和 App 其它地方一样的 24×14 开关。单选框仍保留浏览器自己的行为。
- **设置页和下拉菜单用同一套尺寸。** 设置是一列 48rem，宽于 36rem 时是标签/控件两栏，行高 44px 或 56px；下拉菜单按菜单面板的尺寸打开（触发器 32px，手机上 40px，箭头会转，选中行抬高并带对勾），焦点到处都是 2px 墨色描边。选设备的弹层也遵循同样的规则。
- 在别处登录一台电脑时显示的 hub 地址，现在是 `https://api.droppen.app`。App、主站和下载链接仍是 `my.` 和 `www.`，安装命令不变。

### 迁移到 api.droppen.app

- **新安装连的是 `wss://api.droppen.app`。** 安装脚本、新安装启动的本地服务、以及设备探测，默认都用它；安装命令本身仍是 `https://droppen.app/install.sh`。apex 仍作为临时的机器地址保留，让迁移之前入网的安装继续可用；你自己设置的 hub 仍然优先。
- **迁移之前入网的安装会自己搬过来。** 启动时，状态里还记着 apex 的 agent 会先向 `wss://api.droppen.app` 做一次预登录，只有在十秒内被正式 hub 接受，才会改用新的地址。连不上、或被 hub 拒绝，就保持原来的地址不动，其它什么都不变：同一台机器、同一个账户、同一条链。
- 由 Cloudflare 提供的页面现在跨域调用 `api.` 上的机器 API；它们以前写的是还不会响应的中继地址，结果页面开的中继连接全被关掉。

### 唤醒，和不再响应的中继

- **手机睡醒后，连接立刻就回来。** 页面醒来时会发一次 ping，并要求两秒内得到回应：hub 链路马上重连，对端不回应答的中继和数据流套接字会被换掉，能回应的则保留。以前死掉的套接字看起来还是通的，页面可能要等 25 秒（hub）或 60 秒（中继、数据流）。
- **对端没声音的中继路径不再冻住。** 探测连续两个间隔（10 秒）没有回应，就关闭这条通道并唤醒载体，下一条通道会在活的路由上打开；而不是一直等到 60 秒的静默，指示器停在「20005 ms」附近。因为页面计时器被挂起而跳过的探测会被忘掉，而不是按时间变旧，所以手机解锁不会再重建一条健康的通道；Wi-Fi 和蜂窝网络切换，现在也会像恢复一样唤醒页面。

### VS Code 需要 code-server

- **没装 code-server 时打开 VS Code，会直接说明。** 在没装 code-server 的设备上点「+」→「VS Code」，以前只会以一个光秃秃的 409 失败，且只显示在「+」的提示里；现在服务端先检查 PATH，App 会打开一个对话框：VS Code 运行在 code-server 里，Droppen 不安装它——请先安装（比如装进 `~/.local/bin`），再点一次，不需要重启。对话框里有 code-server 的安装说明链接，英文、两种中文和日文都有；「+」的提示写着「VS Code 需要 code-server」。各 README 把 code-server 列为可选的前提，并说明 `~/.local/bin` 在安装脚本的服务和桌面 App 的服务端的 PATH 里。
