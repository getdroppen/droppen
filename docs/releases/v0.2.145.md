## Droppen App for macOS

`Droppen-0.2.145.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.130 to 0.2.143 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to update*. 0.2.133 and 0.2.134 freeze after an update check that finds nothing newer, but not after one that finds this release, so they update the same way; if yours is frozen now, force-quit it (Option-Command-Esc) and open it again. Version 0.2.129 and older are not guaranteed to upgrade themselves: install this release once by hand — download this DMG and replace the app in Applications, or run the install script again (`curl -fsSL https://droppen.app/install.sh | sh`) — and later releases update themselves as before.

Version 0.3.0-rc.1 has the same number line above 0.2.145 and will not offer this release as an update: if you installed the rc to try A2A, install this DMG by hand to come back to the stable line.

## Droppen App for Linux

The desktop app for Linux, the same app as on the Mac. It needs glibc 2.35 or later (Ubuntu 22.04, Debian 12 and newer), on x86_64 (`x86_64`, `amd64`) or 64-bit Arm (`aarch64`, `arm64`). The AppImage, `Droppen-0.2.145-x86_64.AppImage` or `Droppen-0.2.145-aarch64.AppImage`, is one file that carries its own libraries and updates itself; the .deb, `droppen_0.2.145_amd64.deb` or `droppen_0.2.145_arm64.deb`, is for Debian and Ubuntu. To install it the first time, keep the AppImage in a folder you can write to, make it executable (`chmod +x Droppen-0.2.145-x86_64.AppImage`) and open it; or install the .deb with `sudo apt install ./droppen_0.2.145_amd64.deb` and open Droppen from your app launcher.

The AppImages of Droppen 0.2.140 to 0.2.143 update themselves to this release: they download this release's AppImage for their architecture in the background (they wait while NetworkManager says the connection is metered), check its signature, and write it over the old file, under the same name, the next time you quit, or at once with *Restart to update*. They do not update where you cannot replace the file (the menu says *Move Droppen to a Folder You Can Write to Update*), nor when they run unpacked (`--appimage-extract-and-run`). The .deb does not update itself: install this release's .deb the same way, `sudo apt install ./droppen_0.2.145_amd64.deb` (`droppen_0.2.145_arm64.deb` on Arm). `Droppen-0.2.145-linux-sources.tar` holds the source of the libraries the AppImages carry and of the AppImage runtime; `LIBRARIES-x86_64.txt` and `LIBRARIES-aarch64.txt` list each library with its Ubuntu package and version.

## What's new in v0.2.145

### Native attachments across Claude Code, Codex and ACP

- **Claude Code sessions send native images and PDFs.** Images and PDFs attached to a Claude Code session are now delivered directly as native multimodal `image` and `document` blocks within size budgets, falling back to path references only for unsupported or oversized files. Transcripts resolve attached media cleanly, strip leading `[Image #N]` markers, and render attachment-only turns without losing thumbnails or chips.
- **Codex images render in transcripts and chats validate inline attachments.** Codex chats now validate PNG/JPEG/GIF/WebP images and inline UTF-8 text files; Codex sessions fall back gracefully when an image exceeds limits, drop Claude-specific tool instructions from path suffixes, and parse `local_images` and `input_image` entries so images sent to Codex actually appear in the transcript.
- **ACP negotiates native multimodal content blocks.** ACP drivers now read `PromptCapabilities` from `initialize`, send native `image` and embedded text `resource` blocks when supported (falling back to `resource_link` and path suffixes otherwise), percent-encode `file://` URIs cleanly, and preserve attachment thumbnails and chips when replaying history via `session/load`.
- **Attachment uploads, drafts and cleanup.** Composer uploads now travel on the low-priority `blob` channel class so large files never stall RPC or terminal streams; dotless filenames like `png` are no longer misclassified as images; session composer drafts keep ready attachments across reloads and restore both text and attachments when a send is refused; sent attachments are marked and preserved with their sessions while unreferenced staging uploads older than 24 hours are swept automatically.

### Plugins & ACP

- **Sandboxed cloud plugins and plugins in Screens.** Plugins enabled for cloud access now run inside a sandboxed iframe runtime on `droppen.app` and can be arranged alongside sessions and terminals in Screens.
- **ACP presets and interactive permissions.** Added the Antigravity ACP agent preset, interactive tool-call approval prompts, and per-model effort mapping.

### Desktop app

- **Security hardening.** Hardened cloud sign-in opener handling, scoped `init.js` token delivery, restricted subframe navigation, and tightened the webview CSP.
- **Lifecycle and packaging reliability.** Hardened sidecar startup and shutdown, made desktop state writes atomic, improved single-instance lock handling and log rotation, upgraded Linux container base libraries, and added Launchpad source-archive fallback alongside pool-size comparison fixes for Linux AppImage builds.

### Connection, reliability & performance

- **Relay, agent and browser E2E hardening.** Bounded HTTP header sizes, pre-auth relay sockets, rate-limit wait durations and refused request bodies; hardened relay uplink recovery and ticket renewal; resolved browser E2E channel lifecycle races, added upload/download backpressure on tunneled streams, and tightened connection log redaction.
- **Server and web stability.** Fixed core loop deadlocks and unbounded buffers, hardened outbound webhooks, ACP file reads and PTY shim sockets, fixed web stream bleed and timer/WebSocket leaks, reduced transcript re-renders, preserved archived Codex rollout claims and compressed subagent failure flags, and ranked directory groups by when work started.

### For developers

- Added Biome static linting in CI and split several large modules (`resident.rs`, `routes.rs`, `app_server.rs`, `hub/account.ts`) into focused submodules.
- Decoupled local settings and public pages from cloud/E2E bundles, sped up server/CI test runs, and resolved `esbuild` from Vite in `web/build/plugin-frame.ts` so filtered installs generate third-party notices reliably.

## macOS 版 Droppen App

`Droppen-0.2.145.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

0.2.130 至 0.2.143 会自动更新到这个版本：在后台下载，并在你下次退出时安装；也可以用「重启以更新」立即安装。0.2.133 和 0.2.134 在检查更新、发现没有新版本后会卡死，但发现这个版本时不会，所以同样会正常更新；如果你的 App 现在已经卡住，请强制退出（Option-Command-Esc）后重新打开。0.2.129 及更早的版本不保证能自动升级：请手动安装一次这个版本——下载这个 DMG 替换「应用程序」里的 Droppen，或重新运行安装脚本（`curl -fsSL https://droppen.app/install.sh | sh`）——之后的版本会照常自动更新。

0.3.0-rc.1 的版本号在 0.2.145 之上，不会把它当作更新提示：如果你装了 rc 版试 A2A，请手动安装这个 DMG 回到稳定线。

## Linux 版 Droppen App

Linux 版桌面 App，和 Mac 版是同一个 App。需要 glibc 2.35 或更高版本（Ubuntu 22.04、Debian 12 及更新的版本），支持 x86_64（`x86_64`、`amd64`）和 64 位 Arm（`aarch64`、`arm64`）。AppImage（`Droppen-0.2.145-x86_64.AppImage` 或 `Droppen-0.2.145-aarch64.AppImage`）只有一个文件，自带所需的库，会自动更新；.deb（`droppen_0.2.145_amd64.deb` 或 `droppen_0.2.145_arm64.deb`）适用于 Debian 和 Ubuntu。第一次安装：把 AppImage 放在你可写入的文件夹里，设为可执行（`chmod +x Droppen-0.2.145-x86_64.AppImage`），然后打开它；或者用 `sudo apt install ./droppen_0.2.145_amd64.deb` 安装 .deb，然后从应用启动器打开 Droppen。

0.2.140 至 0.2.143 的 AppImage 会自动更新到这个版本：在后台下载这个版本里对应架构的 AppImage（NetworkManager 显示当前是按流量计费的连接时会等待），校验签名，并在你下次退出时用它覆盖旧文件，文件名不变；也可以用「重启以更新」立即安装。如果你不能替换这个文件（菜单会显示「移到你可写入的文件夹后才能更新」），或者它是解开后运行的（`--appimage-extract-and-run`），它不会更新。.deb 不会自动更新：请用同样的方法安装这个版本的 .deb（`sudo apt install ./droppen_0.2.145_amd64.deb`，Arm 上是 `droppen_0.2.145_arm64.deb`）。`Droppen-0.2.145-linux-sources.tar` 包含 AppImage 自带的库和 AppImage 运行时的源代码；`LIBRARIES-x86_64.txt` 和 `LIBRARIES-aarch64.txt` 列出每个库对应的 Ubuntu 软件包和版本。

## v0.2.145 更新内容

### Claude Code、Codex 与 ACP 原生附件支持

- **Claude Code 会话原生发送图片与 PDF。** 会话中附加的图片和 PDF 在大小限额内直接作为原生多模态 `image` / `document` 块发送，仅在超出限制或不支持的类型时回退为路径引用；转写中正确显示缩略图与附件卡片、去除多余的 `[Image #N]` 标记，并完整支持纯附件消息。
- **Codex 图片转写可见且聊天支持内联校验。** Codex 即时聊天现会校验 PNG/JPEG/GIF/WebP 图片并内联 UTF-8 文本文件；会话中超限图片自动回退路径、去除不属于 Codex 的 Read 工具提示，并正确解析 `local_images` 与 `input_image` 条目，修复此前 Codex 图片在转写中不可见的问题。
- **ACP 协商原生多模态块并保留回放附件。** ACP 驱动会在 `initialize` 阶段读取 `PromptCapabilities`，在 agent 支持时发送原生 `image` 与内嵌文本 `resource` 块（否则回退为 `resource_link` 与路径后缀），规范编码 `file://` URI，并在 `session/load` 回放历史时保留附件缩略图与文件卡片。
- **上传优先级、草稿持久化与按需回收。** 附件上传改走低优先级 `blob` 通道，不再阻塞 RPC 和终端交互；修复无扩展名文件（如 `png`）被误判为图片的问题；会话输入框草稿会同步持久化已上传附件，发送被拒时同时恢复文字与附件；已发送附件会打标记随会话长期保留，仅定期回收超过 24 小时未发送的暂存文件。

### 插件与 ACP

- **沙箱云端插件与 Screens 插件面板。** 开启云端访问的插件现可在 `droppen.app` 上通过沙箱 iframe 运行时加载，并支持与会话、终端一同排布在 Screens 中。
- **ACP 预设与交互式权限。** 新增 Antigravity ACP agent 预设、交互式工具权限审批以及按模型映射的推理强度配置。

### 桌面端 App

- **安全加固。** 加固云端登录弹窗的 opener 隔离、收紧 `init.js` token 作用域与子 iframe 导航限制，并进一步收紧 WebView CSP。
- **生命周期与打包可靠性。** 加固 sidecar 启停与清理、原子化持久化桌面端状态文件、完善单实例锁与日志轮转，升级 Linux 构建容器基础依赖并为源码包收集补充 Launchpad 官方归档兜底及池文件大小比对修复。

### 连接、可靠性与性能

- **中继、Agent 与浏览器端 E2E 通道加固。** 限制中继与 Agent 的 HTTP 头大小、预认证连接数、限流等待上限与拒收请求体边界，增强上行重连与票据续期可靠性；修复浏览器端 E2E 通道生命周期竞态，为隧道流增加上传/下载背压，并收紧连接日志脱敏。
- **服务端与前端稳定性。** 修复核心循环死锁与无界缓冲、加固出站 Webhook / ACP 文件读取 / PTY 套接字安全检查、消除前端流串台与定时器/WebSocket 泄漏、减少转写重渲染、修复 Codex 已归档会话认领与压缩子任务状态缓存，并按工作开始时间排序目录分组。

### 面向开发者

- 在 CI 中引入 Biome 静态检查，并将 `resident.rs`、`routes.rs`、`app_server.rs`、`hub/account.ts` 等大文件拆分为职责清晰的子模块。
- 将本地设置与公开站点 bundle 与云端/E2E 代码解耦、加快服务端与 CI 测试速度，并在 `web/build/plugin-frame.ts` 中改为从 Vite 解析 `esbuild`，确保按子包过滤安装时能稳定生成第三方许可声明。
