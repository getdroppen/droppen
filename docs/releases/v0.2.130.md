## Droppen App for macOS

`Droppen-0.2.130.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.127, 0.2.128 and 0.2.129 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to Update*. Droppen 0.2.125 and 0.2.126 update themselves in two steps: first to 0.2.127, which https://github.com/getdroppen/releases (where they look for updates, now archived) still offers, then from 0.2.127 to this release. Version 0.2.124 and older do not update themselves: download this DMG once and replace the app in Applications.

## macOS 版 Droppen App

`Droppen-0.2.130.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

0.2.127、0.2.128 和 0.2.129 会自动更新到这个版本：在后台下载，并在你下次退出时安装；也可以用「重启以更新」立即安装。0.2.125 和 0.2.126 会分两步自动更新：先更新到 0.2.127（它们检查更新的 https://github.com/getdroppen/releases 已归档，但仍提供 0.2.127），再从 0.2.127 更新到这个版本。0.2.124 及更早的版本不会自动更新：请手动下载一次这个 DMG，替换「应用程序」里的 Droppen。

## What's new in v0.2.130

### Signing up

- **droppen.app's pages say sign-up is open, and the waitlist is for Pro.** droppen.app takes sign-ups without an invite (you verify your e-mail address), so its home, pricing and download pages no longer call Droppen invite-only: the Free plan's button signs you up, and the sign-up form keeps an invite code as an optional field (*have an invite code?*). Pro is not on sale yet, so the waitlist on the pricing page is now for Pro only. The pages follow the Hub's sign-up mode: a Hub that signs up by invite only still shows the invite wording and the waitlist for both plans.

### The local server answers only to its own names

- **Reaching the local server through a reverse proxy, a tunnel or a name of your own now needs `DROPPEN_ALLOWED_HOSTS`.** The local server now answers only requests addressed to an IP address, `localhost`, a local-network name (`mymac`, `*.local`, `*.lan`, `*.home.arpa`, `*.internal`) or a tailnet's `*.ts.net`. If you reach it through a reverse proxy or tunnel under another name (Caddy, Traefik, a Cloudflare Tunnel), add that name to `DROPPEN_ALLOWED_HOSTS` (comma-separated; `*` accepts any name).
- It also answers to the name it is set to listen on (`APP_SERVER__HOST`) and to the hosts in `DROPPEN_ALLOWED_ORIGINS`. A request addressed to any other name gets `403`, with a message that names `DROPPEN_ALLOWED_HOSTS`. The desktop app, the local page at `http://127.0.0.1:<port>`, the `droppen` command, `install.sh` and `tailscale serve` need nothing.
- When droppen.app adds a device from its local page, a `*.lan` address now counts as a local network address too: a tick, not the typed host name a public address asks for.

### Installing, and checking what droppen.app serves

- **`install.sh` checks a signature over the server's checksums.** Before it trusts a checksum, it checks `SHA256SUMS-server` against its signature with the release key pinned in the script, so the files it installs are the ones the release build made, wherever they were downloaded from. It uses `openssl`, which macOS and almost every Linux already have. A signature that does not check out is never accepted.
- Releases before v0.2.130 have no such signature. To install one of them, use that release's own installer: `curl -fsSL https://github.com/getdroppen/droppen/releases/download/<tag>/install.sh | DROPPEN_VERSION=<tag> sh`; or set `DROPPEN_ALLOW_UNSIGNED=1`, which goes by the release's `SHA256SUMS` alone. The same setting installs on a system without `openssl`.
- **`install.sh` downloads over https only.** `DROPPEN_RELEASE_BASE` must be an `https://` address, or plain `http://` on this device (`127.0.0.1`, `localhost`, `[::1]`) for a test server. Any other address is refused before anything is downloaded; it used to be a warning.
- **`scripts/verify-web.mjs` checks a site against the latest release by default, and requires a Content-Security-Policy.** Without `--release`, a site whose build matches only an earlier release fails (`--allow-older` accepts it and says so), and a site that does not say which build it serves is compared with the latest release file by file. A page fails without a `Content-Security-Policy` whose `frame-ancestors` and `object-src` allow only `'none'` or `'self'`; droppen.app's passes. Right after a release, until droppen.app serves it, the default check fails: use `--allow-older` or `--release` (docs/web-integrity.md).

### Your account's keys in the browser

- **Older content keys move into the sealed vault on every device.** Browsers that ran Droppen's earliest builds kept the content keys of the devices that run AI in an older, unsealed form. Only full devices moved them out; now limited devices do too, into their own key vault, sealed with the browser's own key. Each key is taken only if it is exactly the one your account's device chain recorded, and the old copy is deleted only once the sealed copy reads back. When this browser deletes an account's keys (*Sign out and remove this browser*, or a deleted account), these go too, also when the page cannot open the account.
- **A dispute from another tab counts once this page has checked it.** When an identity key renewal is disputed, the device it concerns is isolated. A dispute another tab of this browser passes on now counts in this page once this page has checked its signature itself; one about a renewal this page has not loaded yet keeps the device isolated until the page catches up and checks it.
- **No pairing while an activation is held back.** When a device that came back with the recovery words, or joined with a passkey, activates itself sooner than this device allows, this device holds the activation back and signs nothing but the veto until you approve or remove that device. It now also pairs no device meanwhile, not even one already in the list whose keys never arrived: it first catches up with the account, then says "approve it or remove it first", and the pairing confirmation shows that note and cannot be confirmed. Once you approve or remove the device, pairing works as before.
- **Only an active device can raise the alarm that the account's device list has branched.** A device that runs AI alarms every device of the account when a device's view of that list conflicts with its own. A device that was removed, or whose join is still waiting, now gets the same refusal as any device the account does not let in, and no alarm; your active devices raise it as before. This is a change in the device that runs AI; your browsers and phones need nothing.

### Relays

- **A relay keeps each account's devices that run AI apart.** A device that runs AI signing in again replaces only its own account's earlier connection, and its online status goes to its own account's devices only.
- **A relay refuses tickets that run longer than 15 minutes, or are dated more than 5 minutes ahead of its own clock.** droppen.app's tickets run 15 minutes, so nothing changes for you.
- Both are changes to the relay program, `droppen-relay`: a relay has them once it runs this release. If you run a relay, build its image again from v0.2.130 (README, "Running a relay").

### Also new

- **droppen.app and the app follow your languages.** They now take the first language in your browser's list of preferred languages (in the desktop app, macOS's) that Droppen speaks (English, Simplified Chinese, Traditional Chinese, Japanese), and English when there is none; before, only the first language in the list counted. A language you choose yourself still wins, and the language menus of the public pages, sign-in and sign-up, and the setup guide now have *auto*, which hands the choice back to your browser. The desktop app's own menus, in the window and in the menu bar, and its update messages follow the whole macOS list too. Safari tells a page only its first preferred language, so there a first language Droppen does not speak still means English: choose one in the menu.
- **Edit an env account's variables.** In Settings → Accounts, an account added with a block of environment variables now has *edit* (it had *re-auth*), which opens on the stored block: fixing one value no longer means typing the whole block again, and you can see what is stored. Saving still replaces the whole block, and the account keeps its id, so sessions running under it carry on. The accounts list itself still carries only the variables' names.
- **Security and Droppen are one settings tab, *Access*.** The local login comes first (who is signed in, the password, the signed-in devices), then, on a computer's own page, its link to Droppen, in one sheet. Links to the old tabs open *Access*, and the messages that pointed to them now say Settings → Access.
- **A softer dark theme.** The dark background is a dark graphite instead of near-black, with surfaces, borders and text adjusted to it; small grey labels are easier to read. The desktop app's splash, the terminal and the launch images of the app added to a phone's home screen follow. The light theme is unchanged.
- **droppen.app/security says precisely what the code does.** Its lines now cover this release's changes, and each one that rests on Droppen Hub's own behaviour or policy, rather than on this repository's code, is marked "(Hub)".

## v0.2.130 更新内容

### 注册

- **droppen.app 的页面写明注册已开放，候补名单只针对 Pro。** droppen.app 现在无需邀请即可注册（需要验证邮箱），所以首页、价格页和下载页不再说 Droppen 仅限邀请：免费方案的按钮直接带你注册，注册表单里的邀请码改为选填（「有邀请码？」）。Pro 还没开卖，所以价格页上的候补名单现在只针对 Pro。这些页面跟随 Hub 的注册方式：只接受邀请注册的 Hub，仍显示邀请的说法，两个方案也都仍有候补名单。

### 本地服务端只回应发给它自己名字的请求

- **通过反向代理、隧道或你自己的域名访问本地服务端，现在需要设置 `DROPPEN_ALLOWED_HOSTS`。** 本地服务端现在只回应发往 IP 地址、`localhost`、本地网络名字（`mymac`、`*.local`、`*.lan`、`*.home.arpa`、`*.internal`）或 tailnet 的 `*.ts.net` 的请求。如果你通过反向代理或隧道、用别的名字访问它（Caddy、Traefik、Cloudflare Tunnel），请把那个名字加进 `DROPPEN_ALLOWED_HOSTS`（逗号分隔；`*` 表示接受任何名字）。
- 它也回应它被设置监听的名字（`APP_SERVER__HOST`）和 `DROPPEN_ALLOWED_ORIGINS` 里的主机。发往其它名字的请求会得到 `403`，提示里写明 `DROPPEN_ALLOWED_HOSTS`。桌面 App、`http://127.0.0.1:<端口>` 上的本地页面、`droppen` 命令、`install.sh` 和 `tailscale serve` 都不需要任何设置。
- droppen.app 从设备的本地页面添加设备时，`*.lan` 地址现在也算本地网络地址：只需勾选一下，不需要像公网地址那样输入主机名。

### 安装，以及核对 droppen.app 提供的内容

- **`install.sh` 会核对服务端校验和的签名。** 它在信任校验和之前，先用脚本里固定的发布密钥核对 `SHA256SUMS-server` 的签名，这样无论文件从哪里下载，它安装的都是发布构建做出的那些文件。它使用 `openssl`，macOS 和几乎所有 Linux 都自带。签名核对不上的，一律不接受。
- v0.2.130 之前的版本没有这个签名。要安装其中某个版本，请用那个版本自己的安装脚本：`curl -fsSL https://github.com/getdroppen/droppen/releases/download/<tag>/install.sh | DROPPEN_VERSION=<tag> sh`；或者设置 `DROPPEN_ALLOW_UNSIGNED=1`，只按那个版本的 `SHA256SUMS` 核对。没有 `openssl` 的系统也用这个设置来安装。
- **`install.sh` 只通过 https 下载。** `DROPPEN_RELEASE_BASE` 必须是 `https://` 地址；只有本机（`127.0.0.1`、`localhost`、`[::1]`）上的测试服务器可以用普通的 `http://`。其它地址在下载任何东西之前就会被拒绝；以前只是给出警告。
- **`scripts/verify-web.mjs` 默认按最新版本核对网站，并要求 Content-Security-Policy。** 不带 `--release` 时，构建只与旧版本一致的网站不通过（`--allow-older` 接受它，并写明这一点）；没有说明自己提供哪个构建的网站，会逐个文件与最新版本比对。没有 `Content-Security-Policy`、或者其中的 `frame-ancestors` 和 `object-src` 不是只允许 `'none'` 或 `'self'` 的页面不通过；droppen.app 的通过。刚发布新版本、droppen.app 还没用上它时，默认的核对不通过：请用 `--allow-older` 或 `--release`（见 docs/web-integrity.md）。

### 浏览器里的账户钥匙

- **旧的内容钥匙在每台设备上都会移进封存的保管库。** 用过 Droppen 最早几个版本的浏览器，以一种旧的、未封存的形式保存着可运行 AI 的设备的内容钥匙。以前只有完整设备会把它们移出来；现在受限设备也会，移进它自己的钥匙保管库，用浏览器自己的钥匙封存。每把钥匙只有在与你账户的设备链记录的完全一致时才会被移入，旧副本要等封存后的副本能读回来才会删除。这个浏览器删除某个账户的钥匙时（「退出登录并移除这个浏览器」，或账户已被删除），这些钥匙也会一并删除，页面打不开账户时也一样。
- **来自另一个标签页的争议，要等这个页面核对过才算数。** 身份密钥更换遇到争议时，相关的设备会被隔离。同一浏览器的另一个标签页转来的争议，现在要等这个页面自己核对过它的签名，才在这个页面里算数；如果争议涉及的更换这个页面还没加载到，它会先把设备隔离，等赶上进度、核对之后再说。
- **有激活被暂缓时，不进行配对。** 当一台用恢复词找回、或通过通行密钥加入的设备，比这台设备允许的时间更早地自行激活时，这台设备会暂缓这次激活，在你批准或移除那台设备之前，除了否决之外不签任何条目。现在，在此期间它也不与任何设备配对，连列表里已有、但一直没收到钥匙的设备也不再重新配对：它先与账户同步，然后提示「请先批准或移除它」；配对确认会先显示这条说明，并且无法确认。批准或移除那台设备之后，配对照常进行。
- **只有处于活动状态的设备，才能触发「账户设备列表出现分叉」的警报。** 当某台设备看到的设备列表与可运行 AI 的设备自己的不一致时，后者会向账户的每台设备发出警报。已被移除的设备、或加入还在等待中的设备，现在和账户不允许的任何设备一样，只会被拒绝，不会触发警报；你处于活动状态的设备仍会照常触发。这是可运行 AI 的设备一侧的改动，你的浏览器和手机不需要任何改动。

### 中继

- **中继把各个账户的可运行 AI 的设备分开管理。** 可运行 AI 的设备再次登录时，只会替换它自己账户里之前的连接；它的在线状态也只发给它自己账户的设备。
- **中继拒绝有效期超过 15 分钟、或签发时间比它自己的时钟快 5 分钟以上的票据。** droppen.app 签发的票据有效期就是 15 分钟，所以对你没有影响。
- 这两项都是中继程序 `droppen-relay` 的改动：中继要运行这个版本才会有。如果你自己运行中继，请用 v0.2.130 重新构建它的镜像（见 README 的「Running a relay」）。

### 其它新内容

- **droppen.app 和 App 跟随你的语言。** 它们现在从浏览器（桌面 App 则是 macOS）的首选语言列表里，选第一个 Droppen 支持的语言（英文、简体中文、繁体中文、日文），一个都没有时用英文；以前只看列表里的第一个语言。你自己选的语言仍然优先；公开页面、登录和注册页、设置向导的语言菜单现在都有「自动」，可以把选择交还给浏览器。桌面 App 自己的菜单（窗口里的和菜单栏上的）以及更新提示，也按整个 macOS 列表来选。Safari 只把第一个首选语言告诉网页，所以在 Safari 上，如果第一个语言 Droppen 不支持，仍会显示英文：请在菜单里选一种语言。
- **可以编辑 env 账号的环境变量。** 在「设置 → 账号」里，用一段环境变量添加的账号现在有「编辑」（以前是「重新授权」），打开时会显示已保存的整段变量：改一个值不用再整段重打，也能看到存了什么。保存时仍然整段替换，账号 id 保持不变，所以在它下面运行的会话可以继续。账号列表本身仍然只带变量名。
- **「安全」和「Droppen」两个设置页合并为一个「访问」。** 先是本机登录（谁已登录、密码、已登录的设备），然后在电脑自己的页面上是它与 Droppen 的连接，都在同一页里。指向旧设置页的链接会打开「访问」，原先指向它们的提示现在写的是「设置 → 访问」。
- **更柔和的深色主题。** 深色背景从接近纯黑换成了深石墨色，表面、边框和文字也随之调整；灰色小字更容易看清。桌面 App 的启动画面、终端，以及添加到手机主屏幕的 App 的启动图也一并更新。浅色主题不变。
- **droppen.app/security 准确写明代码做了什么。** 页面内容涵盖了这个版本的改动；凡是依据 Droppen Hub 自身行为或政策、而不是这个仓库代码的条目，都标上了「(Hub)」。
