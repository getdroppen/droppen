## Droppen App for macOS

`Droppen-0.2.138.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.129 to 0.2.137 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to update*. 0.2.133 and 0.2.134 freeze after an update check that finds nothing newer, but not after one that finds this release, so they update the same way; if yours is frozen now, force-quit it (Option-Command-Esc) and open it again. Version 0.2.128 and older are not guaranteed to upgrade themselves: install this release once by hand — download this DMG and replace the app in Applications, or run the install script again (`curl -fsSL https://droppen.app/install.sh | sh`) — and later releases update themselves as before.

## macOS 版 Droppen App

`Droppen-0.2.138.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

0.2.129 至 0.2.137 会自动更新到这个版本：在后台下载，并在你下次退出时安装；也可以用「重启以更新」立即安装。0.2.133 和 0.2.134 在检查更新、发现没有新版本后会卡死，但发现这个版本时不会，所以同样会正常更新；如果你的 App 现在已经卡住，请强制退出（Option-Command-Esc）后重新打开。0.2.128 及更早的版本不保证能自动升级：请手动安装一次这个版本——下载这个 DMG 替换「应用程序」里的 Droppen，或重新运行安装脚本（`curl -fsSL https://droppen.app/install.sh | sh`）——之后的版本会照常自动更新。

## What's new in v0.2.138

### Sessions

- **Changing one session's permission no longer changes the others.** A session with no permission picked for it used to follow the last pick made in any session of the same CLI, so choosing a bypass mode in one session showed it, and sent it, in sessions that never chose it. An existing session now uses its own pick, then the mode its last turn ran in, then the CLI's default. A bypass mode (`bypassPermissions`, `full-access`, `danger-full-access`, `bypass-all`) is kept only where the session picked it itself, so a session that showed one only because of this goes back to the default; pick it again in that session if you want it. New sessions still start from your default.
- **Pictures from the web in a reply load when you ask.** A markdown image whose address is on another site (not a file on your computer and not a GitHub file) is no longer fetched as soon as the reply is on screen: the address is the agent's choice, and fetching it hands that site whatever the address carries. It shows as a card with the picture's description, the site it would come from, *load image* and *open link*. A picture you load stays loaded until the page is reloaded. Pictures from your computer and from GitHub load as before. The desktop app shows the same card.
- **An opening session says what it is waiting for.** When a session takes more than half a second to open, the spinner gets one line under it: *connecting…*, *loading session…*, *from hub · 12/256* while its copy downloads, or *cannot open · retrying*. A fast open still shows only the spinner.
- **Diagrams are drawn by pele.** `mermaid` code blocks are now drawn with [pele](https://github.com/obsidianmd/pele) instead of Mermaid, away from the page's main thread. Structural diagrams take Droppen's colours; charts (pie, timeline, gitGraph, mindmap) take pele's own palette. A diagram that takes longer than 2 seconds to draw, or whose source is longer than 50,000 characters, is shown as its source. The *Mermaid diagrams* setting (rendered or source) works as before.

### Instant chats

- **Chats on Claude Code and Codex take images and files.** On the new-chat page and in later messages you can paste or attach images and files, as in a session. In a Claude chat, images (PNG, JPEG, GIF or WebP, up to 5 MB each) go to the model as images, and text files (UTF-8, up to 100 KB each and 200 KB per message) go into the message; other files are refused. Claude chats still run with no tools. Reopening a chat shows its thumbnails and file chips again. Chats on an API model do not take attachments yet.
- **The new-chat page has the session's composer,** with the same header and notices, and its *+* button now opens a new chat on a phone too.

### On droppen.app

- **The bar says what the connection is doing.** Besides the path and round trip once connected, it says which step a connection is on (*finding the device…*, *Tokyo relay…*, *handshake…*) and, between tries, when the next one is (*no hub · retry 12 s*, *no reply · retry 16 s*). Click the countdown to try at once. A device that refuses this browser has a short label in the bar; the full sentence stays under it. Every state fits on a phone.
- **The offline copy says how far it has caught up.** While the page shows a device's offline copy and the copy is catching up from the hub, the notice reads *updating from hub · sessions 3/7*, with a percentage while a large download runs. It counts sessions, not messages: the hub gives no total of messages before it has sent them all.
- **A recent session opens at once from this browser's copy.** While the device is online, a session this browser keeps a copy of (the 20 opened here and the 5 most recently updated) opens from that copy under *showing the copy saved on this device — updating…*, and the device brings it up to date. Until the device's own state arrives, the composer reads *loading session…* and sends nothing, and the model, effort, permission, account and quota are not shown, so nothing is sent or shown with values that are not the session's own.
- **A large session opened from the offline copy is waited for while it downloads.** Instead of giving up after 8 seconds and showing an empty session, the page keeps waiting while pieces keep arriving (up to a minute) and shows how many it has. An empty session says the device is offline only when the hub says so; otherwise it says there is no copy of this session on this device yet.
- **The offline copy shows no choice that is not the session's.** While the device is offline, the read-only composer no longer shows default model, effort and permission chips (which could be clicked but saved nothing), the quota of this computer's login, or *no account* for a session that runs on an account.
- **A device is renamed on *my devices* only.** The bar no longer has a pencil beside the device's name; rename it from its row menu on *my devices*.

### For developers, plugin authors and relay operators

- The Rust workspace is now the repository root and the crates are under `crates/` (`server-rs/` is gone): build the server with `cargo build -p droppen-server` from the root. The desktop app (`desktop/`) and the update signer stay separate workspaces.
- The relay image builds from `crates/droppen-relay-core/Dockerfile`, still with the repository root as its build context.
- The server is built on gotcha 0.5.2. Its HTTP API, configuration files and `APP_*` variables work as before; the OpenAPI document no longer lists the unused `ErrorBody` schema.
- The server's `plugin cloud <id> on|off` command records whether this install lets droppen.app show a plugin, and `plugin list` shows it. It is off by default, and droppen.app does not show plugins yet.

## v0.2.138 更新内容

### 会话

- **改一个会话的权限，不会再连带改到其他会话。** 以前，没有单独选过权限的会话会跟着同一个 CLI 下任何会话最后一次的选择走，所以在一个会话里选了绕过权限的模式，其他从没选过它的会话也会显示、也会按它发送。现在已有的会话依次用：它自己选的权限、它上一轮实际运行的模式、CLI 的默认值。绕过权限的模式（`bypassPermissions`、`full-access`、`danger-full-access`、`bypass-all`）只在会话自己选了它时才保留，所以只是因为这个问题才显示为绕过的会话，会回到默认值；如果需要，请在那个会话里重新选一次。新会话仍然从你的默认值开始。
- **回复里来自网上的图片，要你点了才加载。** markdown 里的图片如果地址在别的网站上（不是你电脑上的文件，也不是 GitHub 上的文件），不会再在回复出现时立刻加载：地址是 agent 定的，加载它就等于把地址里带的内容交给那个网站。它会显示成一张卡片，上面有图片说明、图片所在的网站，以及「加载图片」和「打开链接」。点过「加载图片」的图片，在页面刷新之前一直保持加载。你电脑上的图片和 GitHub 上的图片照常加载。桌面 App 里也是同样的卡片。
- **打开会话时会说明在等什么。** 会话超过半秒还没打开时，转圈图标下方会多一行字：「连接中…」「读取会话…」、下载副本时的「从云端下载 · 12/256」，或「打不开会话 · 重试中」。很快就打开的会话仍然只转圈。
- **图表改用 pele 绘制。** `mermaid` 代码块现在用 [pele](https://github.com/obsidianmd/pele) 绘制，不再用 Mermaid，而且不占用页面主线程。结构类图表使用 Droppen 的配色；统计类图表（饼图、时间线、gitGraph、思维导图）使用 pele 自带的配色。绘制超过 2 秒、或源码超过 50,000 个字符的图表，会直接显示源码。「Mermaid 图表」设置照常生效。

### 即时聊天

- **Claude Code 和 Codex 的即时聊天可以发图片和文件了。** 在新建聊天页和之后的消息里，都可以像在会话里一样粘贴或附加图片和文件。在 Claude 聊天里，图片（PNG、JPEG、GIF 或 WebP，每张最多 5 MB）以图片形式交给模型，文本文件（UTF-8，每个最多 100 KB，每条消息最多 200 KB）放进消息里；其他文件会被拒绝。Claude 聊天仍然不开放任何工具。重新打开聊天时，缩略图和文件条会照常显示。使用 API 模型的聊天暂时不能带附件。
- **新建聊天页用上了会话的输入框，** 标题栏和提示也和会话一致；手机上点「+」也能新建聊天了。

### droppen.app 上

- **顶栏会说明连接在做什么。** 连上之后照常显示路径和往返延迟；连接过程中会显示正在进行的那一步（「正在查找设备…」「正在连接东京中继…」「握手中…」）；两次重试之间会显示下一次在什么时候（「连不上云端 · 12 秒后重试」「连不上设备 · 16 秒后重试」），点一下倒计时就立刻重试。设备不接受这个浏览器时，顶栏显示一个短标签，完整的说明仍在顶栏下方。所有状态在手机上都能完整显示。
- **离线副本会显示同步到了哪里。** 页面显示设备的离线副本、副本正从云端补数据时，提示会显示「正在从云端更新 · 会话 3/7」，下载较大的副本时还会加上百分比。这里数的是会话，不是消息：云端在发完之前，不会给出消息的总数。
- **最近的会话会先从本浏览器的副本里打开。** 设备在线时，本浏览器保存了副本的会话（在这里打开过的 20 个，以及最近更新的 5 个）会立刻从副本打开，顶部提示「正在显示这台设备上保存的副本 — 更新中…」，设备随后补上最新内容。在设备自己的状态到达之前，输入框显示「读取会话…」，不会发出任何消息，模型、强度、权限、账号和额度也都先不显示，所以不会用不属于这个会话的设置发送或显示。
- **从离线副本打开大会话时，会一直等到下载完成。** 以前 8 秒后就放弃，显示一个空会话；现在只要还在收到新数据，页面就会继续等（最多一分钟），并显示已下载的块数。空会话只有在云端确认设备离线时才说「设备离线」，否则显示「这台设备上还没有这个会话的副本」。
- **离线副本不再显示不属于这个会话的设置。** 设备离线时，只读的输入框下方不再显示默认的模型、强度和权限标签（以前能点开，但选了也存不下），不再显示这台电脑登录账号的额度，绑定了账号的会话也不再显示「无账号」。
- **设备只在「我的设备」里改名。** 顶栏里设备名旁边不再有铅笔图标；请在「我的设备」里该设备那一行的菜单里改名。

### 面向开发者、插件作者和中继运营者

- Rust 工作区现在就是仓库根目录，crate 放在 `crates/` 下（`server-rs/` 已移除）：在根目录用 `cargo build -p droppen-server` 构建服务端。桌面 App（`desktop/`）和更新签名工具仍是各自独立的工作区。
- 中继镜像从 `crates/droppen-relay-core/Dockerfile` 构建，构建上下文仍是仓库根目录。
- 服务端基于 gotcha 0.5.2 构建。HTTP API、配置文件和 `APP_*` 环境变量照常可用；OpenAPI 文档里不再列出没有被引用的 `ErrorBody` schema。
- 服务端的 `plugin cloud <id> on|off` 命令用来记录这台安装是否允许 droppen.app 显示某个插件，`plugin list` 会显示这项设置。它默认关闭，而且 droppen.app 目前还不会显示插件。
