## Droppen App for macOS

`Droppen-0.2.143.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.130 to 0.2.142 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to update*. 0.2.133 and 0.2.134 freeze after an update check that finds nothing newer, but not after one that finds this release, so they update the same way; if yours is frozen now, force-quit it (Option-Command-Esc) and open it again. Version 0.2.129 and older are not guaranteed to upgrade themselves: install this release once by hand — download this DMG and replace the app in Applications, or run the install script again (`curl -fsSL https://droppen.app/install.sh | sh`) — and later releases update themselves as before.

Version 0.3.0-rc.1 has the same number line above 0.2.143 and will not offer this release as an update: if you installed the rc to try A2A, install this DMG by hand to come back to the stable line.

## Droppen App for Linux

The desktop app for Linux, the same app as on the Mac. It needs glibc 2.35 or later (Ubuntu 22.04, Debian 12 and newer), on x86_64 (`x86_64`, `amd64`) or 64-bit Arm (`aarch64`, `arm64`). The AppImage, `Droppen-0.2.143-x86_64.AppImage` or `Droppen-0.2.143-aarch64.AppImage`, is one file that carries its own libraries and updates itself; the .deb, `droppen_0.2.143_amd64.deb` or `droppen_0.2.143_arm64.deb`, is for Debian and Ubuntu. To install it the first time, keep the AppImage in a folder you can write to, make it executable (`chmod +x Droppen-0.2.143-x86_64.AppImage`) and open it; or install the .deb with `sudo apt install ./droppen_0.2.143_amd64.deb` and open Droppen from your app launcher.

The AppImages of Droppen 0.2.140 to 0.2.142 update themselves to this release: they download this release's AppImage for their architecture in the background (they wait while NetworkManager says the connection is metered), check its signature, and write it over the old file, under the same name, the next time you quit, or at once with *Restart to update*. They do not update where you cannot replace the file (the menu says *Move Droppen to a Folder You Can Write to Update*), nor when they run unpacked (`--appimage-extract-and-run`). The .deb does not update itself: install this release's .deb the same way, `sudo apt install ./droppen_0.2.143_amd64.deb` (`droppen_0.2.143_arm64.deb` on Arm). `Droppen-0.2.143-linux-sources.tar` holds the source of the libraries the AppImages carry and of the AppImage runtime; `LIBRARIES-x86_64.txt` and `LIBRARIES-aarch64.txt` list each library with its Ubuntu package and version.

## What's new in v0.2.143

A2A is **not** in this release. It was tried in v0.3.0-rc.1 and has been taken back out to be redesigned. A version 0.3.0-rc.1 chain still loads (its device flag and its A2A accept entries are read), so an account that met the rc keeps working; the A2A screens, routes and proxy are gone.

Most of this release is the session view, from a display audit on a phone and a desktop.

### Sessions

- **Wide content uses the pane.** Tables and fenced code take the full width, and prose keeps its readable measure. A wide table no longer leaves half a desktop unused, and a phone no longer loses its answer column off the side; code wraps as tool output already did. A table that still pans gets a fade at the right edge until its end is in view.
- **The unread marker and the jump-to-bottom button no longer cover the transcript.** Both moved into a narrow strip between the transcript and the composer, so neither sits over the line it is about. The button now appears from the last row with text, not from the scroller's end, so a turn that ends on consumed tool results no longer leaves it up over readable lines.
- **Failure and background work read plainly.** A failed step group ends its count with a red ✗ instead of a ×. A successful tool row says nothing; a failure says `failed · exit N`; background work says `background`. A failed row keeps the full danger colour instead of a tint that went unreadable on near black.
- **A run in flight can be watched.** The newest fold of a turn stays open while the turn runs, so the steps can be followed one by one instead of the turn reading as one growing `8 steps` line. It folds again when the turn ends, and a group you opened by hand stays open.
- **Opening a session lands on a row's start.** The first view is brought to the start of the row the top edge would cut through, so the first line on screen is no longer a continuation whose head is above the fold. The window is the first 1.2 s, or until your first wheel, touch or pointer press.
- **Thinking rows look like something that opens**, with the same caret as a step group rather than a line that ends in an ellipsis.
- **Droppen's own words are system lines.** An account rotation or a recovered quota written into a transcript in Droppen's name used to be drawn as if you had said it, with a `[Droppen]` marker on show; it is now a system line, and the marker is hidden.
- **Another session's message shows its sender.** A message that arrives in a `<cross-session-message …>` envelope becomes a `cross-session message from <name>` chip over the sender's own words, and the envelope is off. A session list row says the sender's first line as its title.
- **Smaller transcript fixes.** A wrapped inline code span is one tinted run rather than a bordered box per line; a heading no longer leaves one or two characters alone on its last line; a system line and a tool result clamp to two lines instead of truncating to one (the answer to a question the agent asked was cut off right after the question on a phone); a system line with no body no longer draws an empty fold; a quota gauge with 1% left draws two pixels rather than a fifth of one.

### Questions

- **A question card's draft survives leaving and coming back.** What you typed into a question, answered or not, comes back when you return to the session.
- **A pending question holds the composer's send.** With a question waiting for an answer, the composer no longer sends into the gap and loses the words; it says what it is waiting for.

### Claude Code and ACP

- **A failed local command shows its reason.** `/compact` over the 100-image request limit dies inside the CLI with "API Error: 400 too many images", and the command chip used to stay bare, so a compact that did nothing looked like the command had stopped working. The command's stderr now appears under it, marked `failed` in the danger colour.
- **A tool call's later title and input reach its line.** An ACP agent may announce a call with only its tool name and send the real title and input in the first update. The line showed the bare name and had nothing to expand; it now fills in with the update.

### For developers

- **An rc can be released from a pull request.** A `vX.Y.Z-rc.N` tag is admitted when its commit is on main or on an open pull request to main from this repository (a merged one, too, for a re-run); a stable tag still needs main. The rc notes carry a bilingual test-release banner and name no app file: an rc is server-only. `scripts/cut-rc.sh` does the mechanics. The summary of a run tells the approver which pull request, its checks and any change under the signing-sensitive scripts.
- **The Linux packaging accepts a prerelease version**, so a branch whose source carries an rc version still builds in CI. It also rides out two Ubuntu archive defects: apt update/install/`apt-get source` retry briefly, and a source version the archive has already moved past its index is taken from `pool/main` and checked against the size and sha256 in its `.dsc` (HTTPS on redirects too).
- **A `.gitleaksignore`** records two fixture findings so the required secret scan does not flag the session-proxy test token in history.
- **Version numbering.** The source version goes from `0.3.0-rc.1` back to `0.2.143`: A2A was a prerelease, so the stable line continues at 0.2.x. Version 0.3.0 will be the redesign that follows.
- Nothing changes on the wire for the transcript fixes: they are display and parsing only.

## macOS 版 Droppen App

`Droppen-0.2.143.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

0.2.130 至 0.2.142 会自动更新到这个版本：在后台下载，并在你下次退出时安装；也可以用「重启以更新」立即安装。0.2.133 和 0.2.134 在检查更新、发现没有新版本后会卡死，但发现这个版本时不会，所以同样会正常更新；如果你的 App 现在已经卡住，请强制退出（Option-Command-Esc）后重新打开。0.2.129 及更早的版本不保证能自动升级：请手动安装一次这个版本——下载这个 DMG 替换「应用程序」里的 Droppen，或重新运行安装脚本（`curl -fsSL https://droppen.app/install.sh | sh`）——之后的版本会照常自动更新。

0.3.0-rc.1 的版本号在 0.2.143 之上，不会把它当作更新提示：如果你装了 rc 版试 A2A，请手动安装这个 DMG 回到稳定线。

## Linux 版 Droppen App

Linux 版桌面 App，和 Mac 版是同一个 App。需要 glibc 2.35 或更高版本（Ubuntu 22.04、Debian 12 及更新的版本），支持 x86_64（`x86_64`、`amd64`）和 64 位 Arm（`aarch64`、`arm64`）。AppImage（`Droppen-0.2.143-x86_64.AppImage` 或 `Droppen-0.2.143-aarch64.AppImage`）只有一个文件，自带所需的库，会自动更新；.deb（`droppen_0.2.143_amd64.deb` 或 `droppen_0.2.143_arm64.deb`）适用于 Debian 和 Ubuntu。第一次安装：把 AppImage 放在你可写入的文件夹里，设为可执行（`chmod +x Droppen-0.2.143-x86_64.AppImage`），然后打开它；或者用 `sudo apt install ./droppen_0.2.143_amd64.deb` 安装 .deb，然后从应用启动器打开 Droppen。

0.2.140 至 0.2.142 的 AppImage 会自动更新到这个版本：在后台下载这个版本里对应架构的 AppImage（NetworkManager 显示当前是按流量计费的连接时会等待），校验签名，并在你下次退出时用它覆盖旧文件，文件名不变；也可以用「重启以更新」立即安装。如果你不能替换这个文件（菜单会显示「移到你可写入的文件夹后才能更新」），或者它是解开后运行的（`--appimage-extract-and-run`），它不会更新。.deb 不会自动更新：请用同样的方法安装这个版本的 .deb（`sudo apt install ./droppen_0.2.143_amd64.deb`，Arm 上是 `droppen_0.2.143_arm64.deb`）。`Droppen-0.2.143-linux-sources.tar` 包含 AppImage 自带的库和 AppImage 运行时的源代码；`LIBRARIES-x86_64.txt` 和 `LIBRARIES-aarch64.txt` 列出每个库对应的 Ubuntu 软件包和版本。

## v0.2.143 更新内容

这个版本**不含** A2A。A2A 在 v0.3.0-rc.1 里试过，现在拿回去重新设计。0.3.0-rc.1 写过的链仍然能读（它的设备标志位和 A2A 接受条目仍会被解析），所以碰过 rc 的账号可以继续用；A2A 的界面、路由和代理都已移除。

这个版本主要是会话界面，起因是手机和桌面各做了一次显示审查。

### 会话

- **宽内容用整个面板。** 表格和围栏代码占满宽度，正文保持可读的行宽。宽表格不再让桌面空掉一半，手机也不再丢掉侧边的答案列；代码和工具输出一样换行。仍然需要横向平移的表格会在右缘出现渐隐，滚到末尾就消失。
- **未读标记和回到底部按钮不再盖住转写。** 两者都移到转写和输入框之间的窄条里，不再压在它们指的那一行上。按钮现在从最后一行有文字的记录算起，而不是从滚动容器末尾算，所以以已消费的工具结果结尾的一轮不再把它留在可读的行上方。
- **失败和后台工作读得明白。** 失败的步骤组在计数末尾用红色的 ✗，而不是看起来像乘号的 ×。成功的工具行不写状态；失败写 `failed · exit N`；后台工作写 `background`。失败行保留完整的危险色，而不是在近黑背景上读不清的淡色。
- **进行中的一轮可以看着走。** 一轮里最新的折叠在运行期间保持展开，可以一步步跟着看，而不是整轮只显示成一行不断变长的 `8 steps`。回合结束会重新折叠；你手动打开的组保持打开。
- **打开会话会落在某一行的开头。** 第一次进入画面时，上缘会切到的那一行会被带到行首，屏幕上第一行不再是没有头部的续行。这个窗口是打开后的 1.2 秒，或者到你第一次滚轮、触摸或按下指针。
- **思考行看起来是可以展开的东西**，和步骤组用同一个展开箭头，而不是以省略号结尾的行。
- **Droppen 自己的话变成系统行。** 以 Droppen 之名写进转写的账号轮换、配额恢复，以前会被画成像是你说的，还露出 `[Droppen]` 标记；现在是系统行，标记不再显示。
- **另一个会话的消息会显示发送者。** 装在 `<cross-session-message …>` 信封里的消息会变成发送者的话上方的 `cross-session message from <name>` 小片，信封不再显示。会话列表的一行会用发送者的第一行作为标题。
- **转写的小修。** 换行的行内代码是一整段带底色的文字，而不是每行一个带边框的盒子；标题不再在最后一行只留一两个字；系统行和工具结果截到两行，而不是截成一行（手机上 agent 提问的回答会在问题后直接被切掉）；没有正文的系统行不再画一个空的折叠；配额只剩 1% 时仪表画两个像素，而不是五分之一个像素。

### 提问

- **问题卡里的草稿在离开又回来后会保留。** 你给问题写的内容，无论答没答，回来时都还在。
- **有待答问题时，输入框会挡住发送。** 有提问在等回答时，输入框不再把话发进空隙里丢掉，而是说明在等什么。

### Claude Code 与 ACP

- **失败的本地命令会显示原因。** `/compact` 超过 100 张图的请求上限时，会在 CLI 里报 "API Error: 400 too many images" 挂掉，而命令小片以前是空的，于是一次什么都没做的压缩看起来像命令坏了。命令的 stderr 现在显示在它下面，用危险色标 `failed`。
- **工具调用后来的标题和输入会到达它那一行。** ACP agent 可以只带着工具名宣布一次调用，把真正的标题和输入放在第一次更新里。那一行以前只显示光秃秃的名字、也没有东西可展开；现在会补上更新。

### 给开发者

- **rc 可以从 PR 发。** 当提交在 main 上，或在以 main 为 base 的本仓库 open PR 上（已合并的也可以，便于重跑）时，接受 `vX.Y.Z-rc.N` tag；正式 tag 仍然必须在 main。rc 说明带双语测试版横幅，且不写 App 文件：rc 是只有服务端的。机制在 `scripts/cut-rc.sh`。运行的摘要会告诉审批人哪个 PR、它的检查，以及签名相关脚本的任何改动。
- **Linux 打包接受预发布版本**，所以源码是 rc 版本的分支在 CI 里也能构建。同时扛住 Ubuntu 归档的两个缺陷：apt update/install/`apt-get source` 会短暂重试；归档索引已经走过某个源码版本时，从 `pool/main` 取同一个版本，并按它 `.dsc` 里的 size 和 sha256 校验（重定向也要求 HTTPS）。
- **`.gitleaksignore`** 记录了两条 fixture 发现，免得必需的密钥扫描把历史上 session-proxy 的测试 token 报出来。
- **版本号。** 源码版本从 `0.3.0-rc.1` 写回 `0.2.143`：A2A 是预发布，稳定线继续在 0.2.x。0.3.0 会是之后的重新设计。
- 转写的修复不改线上格式，只涉及显示和解析。
