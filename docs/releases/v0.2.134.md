## Droppen App for macOS

`Droppen-0.2.134.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.127 to 0.2.133 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to Update*. Droppen 0.2.125 and 0.2.126 update themselves in two steps: first to 0.2.127, which https://github.com/getdroppen/releases (where they look for updates, now archived) still offers, then from 0.2.127 to this release. Version 0.2.124 and older do not update themselves: download this DMG once and replace the app in Applications.

## macOS 版 Droppen App

`Droppen-0.2.134.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

0.2.127 至 0.2.133 会自动更新到这个版本：在后台下载，并在你下次退出时安装；也可以用「重启以更新」立即安装。0.2.125 和 0.2.126 会分两步自动更新：先更新到 0.2.127（它们检查更新的 https://github.com/getdroppen/releases 已归档，但仍提供 0.2.127），再从 0.2.127 更新到这个版本。0.2.124 及更早的版本不会自动更新：请手动下载一次这个 DMG，替换「应用程序」里的 Droppen。

## What's new in v0.2.134

### Sessions on ACP agents

- **A session can run on any agent that speaks ACP.** Besides Claude Code and Codex, a new session can start on any program that speaks the [Agent Client Protocol](https://agentclientprotocol.com) over stdio, and you can set up several. The new session's agent chip lists Claude Code, Codex and your ACP agents, and the model and effort pickers offer what that agent offers. Messages sent while the agent is busy wait in a queue you can see and take back; ⏹ stops the turn. Each session records the agent it started on and is always resumed with it.
- **Settings → Agents & accounts.** The accounts page is now *Agents & accounts*, with three tabs: Claude Code and Codex keep their accounts as before, and ACP has one card per agent. Add one from a preset (Bub or OpenCode; the card says whether its command is on the PATH) or give any command line, with its arguments and extra environment variables, of which only the names are ever shown back. *Check* starts the agent, sends `initialize`, reads what it says it can do and stops it; nothing reaches a model. A details dialog shows what the check found and, to a device that manages the computer, why it failed. A tab's label carries an amber or red mark and a count when something there needs you, and links to the old page still open it.
- **An agent that fails stays in view.** In the new-session picker an agent whose last check failed is red, and can still be picked; a red notice then links to its details. Editing an agent's command, arguments or environment restarts its sessions' processes: an idle one at once, a busy one after its turn. Removing an agent keeps its sessions listed and readable; they continue once an agent with the same id is added again.
- **Not yet.** Steering a running turn, scheduled tasks and instant chats do not run on ACP agents, and sessions started in other clients are not listed. The agent runs under the server: a server restart cuts a running turn short (what it streamed is kept), and the next message reopens the session. An idle agent exits after 30 minutes. The agent can run commands and read or write files through Droppen, as the user it runs as; Droppen declines its permission requests.

### Reading a session

- **Math is typeset.** `$…$` and `\(…\)` inline, `$$…$$` and `\[…\]` displayed, in session and instant-chat messages. Code stays as written, and so do prices and shell variables (`$5 and $10`, `$HOME`). Click a formula to copy its TeX. Settings → General → *message rendering* → *LaTeX math* switches between *rendered* (the default) and *source*, the text as it was shown before.
- **Mermaid diagrams are drawn.** A ```` ```mermaid ```` block becomes the flowchart or sequence diagram it describes, at its natural size, and scrolls sideways when it is wider than the message; each diagram has its own control to show its source. *Mermaid diagrams*, in the same group, switches them all between *rendered* (the default) and *source*. A diagram is shown as a picture, so links and styles inside it cannot reach the page.
- **Subagents under their session.** Turn on *subagent tree* in Settings → General (it is off by default), and a session that delegated work lists its subagents beneath it in the sidebar, folded, nested ones a level further in, each with its status, name, role and unread mark. A Claude subagent opens on a page of its own that leads back to its parent; a Codex subagent opens as a read-only session that says whose subagent it is. Forked or continued conversations are not subagents.

### Plugins, installed on the computer

- **Plugins are installed into an instance while it runs.** Settings → Plugins → *Install from file…* takes a plugin's `.tgz` and asks first, because a plugin runs inside the page with no sandbox, signed in as you, terminals included. `droppen plugin install <file.tgz>` and `droppen plugin uninstall <id>` do the same from a shell. Uninstalling keeps the plugin's documents for a later install. A plugin is served to the computer's own pages only: pages from droppen.app never load, list or see one.
- **A plugin this version cannot run is named, not dropped.** One you switched on that does not work with this version of Droppen keeps its rail entry with a warning; its page says why and what to do, and Settings → Plugins shows the problem. Switching it off puts it away.
- Plugins are no longer built into the web app (`distribution.json`, `DROPPEN_DISTRIBUTION`): install them at runtime instead.

### Faster first loads

- **The local server compresses the web app.** Its own files go out with brotli or gzip, whichever the browser takes, at about a quarter to a third of their size. API answers, feeds and terminals are sent as they are.
- **The first page loads only what it needs.** The computer's own pages no longer load the code only droppen.app's pages use, and on both, the translations of languages you do not read and the views other than the session list load when they are first needed. The first frame is in your language: the page waits up to three seconds for its translations, then draws in English and switches when they arrive. Offline, the app keeps the languages you read.
- **The other views are fetched ahead.** Once the first page is drawn, the other views' files are fetched in the background, one view at a time while the page is idle, so opening one later does not wait on the network; on droppen.app this starts from *My devices* too. Nothing is fetched ahead when the browser asks to save data or the connection is 2G or slower.
- A page whose files a newer release replaced reloads itself once; if it still cannot load, it says *the page could not be loaded*, with *retry* and *reload*.

### Also new

- **A lifted dark theme.** The dark theme's background is a cool graphite instead of near-black, and the light theme's text is the same graphite, so the two themes are each other's inverse.
- On *My devices*, a tall card (an open renewal panel or warning) no longer stretches the card beside it.
- On droppen.app, *server updated — reload when convenient* no longer shows on every load, where reloading never cleared it: the page took the version in its offline copy for the one the computer runs. A computer that updates while the page is open still shows it.
- The sign-in and sign-up form on droppen.app no longer waits for, or retries, a request for the sign-up rules: they are written in the page.
- The browser refuses a page of the hub's streams that is larger than the protocol allows before reading all of it, and tries again, as the computer's own client already did.
- Internal cleanup across the server, the web app and the build scripts (duplicates merged, large files split, dead code removed); no change in behaviour beyond what is listed here.

### The command line

- **`droppen --help` is in clap's format.** It opens with a one-line description, the usage line and the list of commands, one line each, then prints the whole usage text it always did. Some refusals are now worded the clap way (an unexpected argument, a missing value), followed by the command's usage as before. What every command accepts and refuses, and its exit codes, are unchanged.
- The usage text no longer says that a new instance inherits the machine's accounts: accounts belong to one instance, and another instance on the same machine has its own.
- Sessions started by this release have only `droppen-notify` on their PATH; the old name, `rh-notify`, is no longer added. Sessions already running keep theirs.
- `droppen-update-manifest`, the release tool that writes and checks the desktop app's `latest.json`, refuses unknown options, `--name=value` and extra words, which it used to ignore.

### Switches that are on or off

- **Five switches that are on by default turn off for any word but an on word.** `DROPPEN_AGENT_LINK`, `DROPPEN_AGENT_CONTROL`, `DROPPEN_SESSION_LOG`, `DROPPEN_AGENT_RELAYS` and `DROPPEN_AGENT_DIRECT` stay on when unset or empty, and for `1`, `true`, `yes` or `on` in any case; `0`, `false`, `off`, `no` or any other word turns them off. Before, the first three went off only for exactly `0`, and the last two took `false`, `off` and `no` only in lower case.
- **The insecure-endpoint opt-ins need an on word.** `DROPPEN_PUSH_ALLOW_INSECURE_ENDPOINT` and `DROPPEN_NOTIFY_ALLOW_INSECURE_ENDPOINT`, which allow a plain-HTTP endpoint on this computer for Web Push and for Bark, used to turn on whenever they were set, `0` and `false` included. Now only `1`, `true`, `yes` or `on` turns one on: if you set one to anything else, set it to `1`.

### Old environment names are going away

- **The server's pre-rename environment names are deprecated, and stop working in v0.2.135.** This release announces it: v0.2.134 still reads the old name when the new one is unset, and notes once per name that it is deprecated and stops working in v0.2.135. Set the `DROPPEN_*` name with the same value instead. These are the old names, by group:
  - Files and configuration: `REMOTE_HAND_DATA_DIR`, `REMOTE_HAND_CONFIG_DIR`, `REMOTE_HAND_CLAUDE_LOCAL_ROOT`, `REMOTE_HAND_CLAUDE_MANAGED_ROOT`, `REMOTE_HAND_SHIM_BIN`.
  - Push and notifications: `REMOTE_HAND_PUSH_CONTACT`, `RH_PUSH_ALLOW_INSECURE_ENDPOINT`, `RH_NOTIFY_ALLOW_INSECURE_ENDPOINT`.
  - Requests and recordings: `RH_ALLOWED_ORIGINS`, `RH_SESSION_LOG`, `RH_SESSION_LOG_MAX_MB`.
  - Running the CLIs and accounts: `RH_IDLE_TIMEOUT_MS`, `RH_STALL_MS`, `RH_INTERRUPT_STEP_MS`, `RH_WATCHDOG_INTERVAL_MS`, `RH_AWAIT_BACKGROUND_MS`, `RH_RESIDENT_IDLE_MS`, `RH_STEER_SETTLE_MS`, `RH_TASK_ROOT`, `RH_ROTATE_AHEAD_PERCENT`, `RH_USAGE_FALLBACK_MS`.
  - The cloud agent and the hub it signs in to: `RH_HUB_DEFAULT`, `RH_HUB_API_TRAFFIC`, `RH_AGENT_CONTROL`, `RH_AGENT_LINK`, `RH_AGENT_DIRECT`, `RH_AGENT_DIRECT_STUN`, `RH_AGENT_RELAYS`, `RH_AGENT_RELAY_INSECURE`, `RH_AGENT_MIGRATE_WITHIN_SECS`, `RH_AGENT_STATUS_CLI`, `RH_AGENT_SYNC_DAYS`, `RH_AGENT_SYNC_EXTERNAL`, `RH_AGENT_COMPACT_RECORDS`, `RH_AGENT_COMPACT_EVERY_SECS`, `RH_AGENT_COMPACT_IDLE_SECS`, `RH_AGENT_COMPACT_OLDEST_SECS`.
  - Names Droppen sets for the programs it starts: `RH_SUPERVISED`, `RH_DESKTOP_APP`, `RH_NOTIFY_URL`, `RH_NOTIFY_TOKEN`; their `DROPPEN_*` names take over too.
- Already gone in this release: building the server from source reads only `DROPPEN_BUILD_REV` and `DROPPEN_ALLOW_MISSING_WEB_DIST`, no longer `RH_BUILD_REV` and `RH_ALLOW_MISSING_WEB_DIST`.

### The relay's old environment names are going away

- **The relay's pre-rename environment names are deprecated, and stop working in v0.2.135.** This release announces it: v0.2.134 still reads the old name when the new one is unset, and notes once per name that it is deprecated and stops working in v0.2.135. Relay operators run the open-source relay themselves, so set the `DROPPEN_RELAY_*` name with the same value instead. The old names are `RH_RELAY_HUB`, `RH_RELAY_ORIGIN`, `RH_RELAY_KEY`, `RH_RELAY_STATE_DIR`, `RH_RELAY_REGISTRATION_TOKEN`, `RH_RELAY_ID`, `RH_RELAY_TICKET_KEYS`, `RH_RELAY_BIND`, `RH_RELAY_TRUST_PROXY`, `RH_RELAY_MAX_CONNS` and `RH_RELAY_DRAIN_SECS`. (`RH_HUB_API_TRAFFIC`, the hub-API traffic capture the relay shares with the other programs, is in the server's list above.)

### Coming from 0.2.124 or older

- **An install older than 0.2.125 is no longer migrated.** One that updates straight to this release does not carry over what it still kept only in its old files: Claude and Codex accounts (sign the CLIs in again), custom titles, archived marks, per-session model and effort picks, read marks, apps, scheduled tasks, saved screen layouts, the chat provider's address and key, the Bark endpoint, push subscriptions, and sign-ins to the local page. The old files stay on disk, unread. An install that has run 0.2.125 or later is not affected.
- Accounts that builds older than 0.2.37 kept for the whole machine are no longer copied into an instance: an install updating straight from such a build, or a new instance on that machine, starts at setup. `droppen open`, `droppen user add <name>` or `droppen setup-code` on that machine gets you in.

## v0.2.134 更新内容

### 在 ACP 智能体上跑会话

- **会话可以跑在任何说 ACP 的智能体上。** 除了 Claude Code 和 Codex，新建会话还可以用任何通过 stdio 说 [Agent Client Protocol](https://agentclientprotocol.com) 的程序，而且可以配置多个。新建会话时的智能体选择里列着 Claude Code、Codex 和你的 ACP 智能体，模型和推理强度的选项就是该智能体自己提供的那些。智能体忙时发出的消息会排队，你能看到，也能撤回；⏹ 停止当前回合。每个会话记下它启动时用的智能体，之后恢复时总是用它。
- **设置 →「智能体与账号」。** 原来的账号页现在叫「智能体与账号」，有三个标签：Claude Code 和 Codex 里还是原来的账号，ACP 里每个智能体一张卡片。可以从预设添加（Bub 或 OpenCode；卡片会写明它的命令在不在 PATH 上），也可以填任意命令行，连同参数和额外的环境变量；环境变量只回显名字，不回显值。「检查」会启动智能体、发送 `initialize`、读出它声明的能力，然后停掉它，不会向模型发任何东西。详情对话框里有检查的结果；失败的原因只给能管理这台电脑的设备看。某个标签里有需要你处理的事时，标签上会有一个琥珀色或红色的标记和数量；指向原来账号页的链接仍然能打开它。
- **出问题的智能体不会消失。** 新建会话时，上次检查失败的智能体显示为红色，但仍然可以选；选中后会出现一条红色提示，链接到它的详情。改了智能体的命令、参数或环境变量，它的会话进程会重启：空闲的立即重启，忙的在当前回合结束后重启。删除一个智能体不会删除它的会话：会话仍在列表里、可以阅读；重新添加同一 id 的智能体后就能继续。
- **暂不支持。** ACP 智能体上还不能 steer 正在运行的回合，也不能跑定时任务和即时聊天；在其他客户端里开的会话不会列出来。智能体是服务端的子进程：服务端重启会中断正在运行的回合（已输出的内容保留），下一条消息会重新打开会话。空闲 30 分钟后智能体进程退出。智能体可以通过 Droppen 运行命令、读写文件，身份是运行它的那个用户；它的权限请求一律被 Droppen 拒绝。

### 阅读会话

- **公式会排版。** 行内的 `$…$` 和 `\(…\)`、独立显示的 `$$…$$` 和 `\[…\]`，在会话和即时聊天的消息里都会排版。代码保持原样，价格和 shell 变量也一样（`$5 and $10`、`$HOME`）。点一下公式就复制它的 TeX。设置 → 通用 →「消息渲染」→「LaTeX 公式」可以在「渲染」（默认）和「源码」之间切换，「源码」就是以前的显示方式。
- **Mermaid 图表会画出来。** ```` ```mermaid ```` 代码块会画成它描述的流程图或时序图，保持原本的大小，比消息宽时可以横向滚动；每张图都有自己的按钮，可以切换显示源码。同一组里的「Mermaid 图表」可以把它们全部在「渲染」（默认）和「源码」之间切换。图表以图片的形式显示，所以图里的链接和样式碰不到页面。
- **子代理列在会话下面。** 在设置 → 通用里打开「子代理树」（默认关闭），委派过任务的会话会在侧边栏里把子代理列在它下面：默认折叠，嵌套的再缩进一层，每个都有状态、名称、角色和未读标记。Claude 的子代理在自己的页面打开，页面上可以回到它的上一级；Codex 的子代理以只读会话打开，并写明它是谁的子代理。分叉或续接出来的对话不算子代理。

### 插件，装在电脑上

- **插件在实例运行时安装。** 设置 →「插件」→「从文件安装…」接受插件的 `.tgz`，安装前会先问你：插件在页面里运行、没有沙箱、以你的身份登录，终端也能用。在 shell 里用 `droppen plugin install <file.tgz>` 和 `droppen plugin uninstall <id>` 也一样。卸载会保留插件的文档，留给以后重新安装。插件只提供给这台电脑自己的页面：droppen.app 的页面从不加载、列出或看到任何插件。
- **这个版本跑不了的插件会写明，而不是消失。** 你打开过、但与这个版本的 Droppen 不兼容的插件，会在侧边栏里保留入口并带一个警告；它的页面会说明原因和怎么办，设置 →「插件」里也会显示问题。把它关掉就收起来了。
- 插件不再编进 Web App（`distribution.json`、`DROPPEN_DISTRIBUTION`）：请改为运行时安装。

### 首次加载更快

- **本地服务端会压缩 Web App。** 它自己的文件按浏览器支持的方式用 brotli 或 gzip 发送，大小只有原来的约四分之一到三分之一。API 应答、数据流和终端照原样发送。
- **首页只加载它需要的东西。** 电脑自己的页面不再加载只有 droppen.app 的页面才用的代码；两边都一样，你不读的语言的翻译、以及会话列表以外的视图，都在第一次需要时才加载。第一帧就是你的语言：页面最多等三秒翻译，超时就先用英文画出来，翻译到了再切换。离线时，App 会保留你读的语言。
- **其他视图会提前取好。** 首页画出来之后，其他视图的文件会在后台、趁页面空闲一个视图一个视图地取好，之后打开时不用等网络；在 droppen.app 上，从「我的设备」开始也一样。浏览器要求省流量、或网络是 2G 及更慢时，不会提前取。
- 文件已被新版本替换的页面会自己刷新一次；仍然加载不了时，会显示「页面加载失败」，并提供「重试」和「刷新」。

### 其它新内容

- **更亮一些的深色主题。** 深色主题的背景从接近纯黑换成了偏冷的石墨色，浅色主题的文字也用同样的石墨色，两套主题正好互为反色。
- 「我的设备」里，一张较高的卡片（展开了续期面板或警告）不再把旁边的卡片也撑高。
- 在 droppen.app 上，「服务端已更新 — 方便时刷新页面」不再每次加载都出现、刷新也消不掉：页面以前把离线副本里的版本当成了电脑实际运行的版本。页面开着时电脑真的更新了，仍然会显示。
- droppen.app 的登录和注册表单不再等待、也不再重试获取注册规则的请求：这些规则直接写在页面里。
- 浏览器读取 hub 数据流的分页时，超过协议上限的页面在读完之前就会被拒绝，然后重试；电脑自己的客户端本来就是这样。
- 服务端、Web App 和构建脚本做了内部清理（合并重复代码、拆分大文件、删除无用代码）；除了这里列出的内容，行为没有变化。

### 命令行

- **`droppen --help` 改用 clap 的格式。** 开头是一行简介、用法行和命令列表，每个命令一行，后面仍然是以前那份完整的用法说明。有些拒绝的提示改成了 clap 的措辞（多出的参数、缺少的值），后面照旧附上该命令的用法。每个命令接受什么、拒绝什么，以及退出码，都没有变。
- 用法说明不再说新实例会继承本机的账号：账号属于一个实例，同一台机器上的另一个实例有自己的账号。
- 这个版本启动的会话，PATH 里只有 `droppen-notify`，不再添加旧名字 `rh-notify`。已经在运行的会话保留原来的。
- 发布工具 `droppen-update-manifest`（生成和检查桌面 App 的 `latest.json`）会拒绝未知选项、`--name=value` 和多余的参数，以前这些都被忽略。

### 开关变量

- **五个默认开启的开关，遇到不是「开」的词就关闭。** `DROPPEN_AGENT_LINK`、`DROPPEN_AGENT_CONTROL`、`DROPPEN_SESSION_LOG`、`DROPPEN_AGENT_RELAYS` 和 `DROPPEN_AGENT_DIRECT` 在未设置或为空时，以及值为 `1`、`true`、`yes`、`on`（不分大小写）时保持开启；`0`、`false`、`off`、`no` 或其它任何词都会关闭它们。以前前三个只有恰好是 `0` 才关闭，后两个的 `false`、`off`、`no` 只认小写。
- **不安全端点的开关需要明确写「开」。** `DROPPEN_PUSH_ALLOW_INSECURE_ENDPOINT` 和 `DROPPEN_NOTIFY_ALLOW_INSECURE_ENDPOINT` 允许 Web Push 和 Bark 使用本机的明文 HTTP 端点；以前只要设置了就开启，`0` 和 `false` 也算。现在只有 `1`、`true`、`yes` 或 `on` 才开启：如果你设的是别的值，请改成 `1`。

### 旧的环境变量名即将移除

- **服务端改名前的环境变量名已弃用，v0.2.135 起不再生效。** 这个版本发出通知：v0.2.134 在新名字没设时仍然读旧名字，并且每个旧名字只提示一次它已弃用、v0.2.135 起不再生效。请改用同值的 `DROPPEN_*` 名字。下面按用途分组列出这些旧名字：
  - 文件与配置：`REMOTE_HAND_DATA_DIR`、`REMOTE_HAND_CONFIG_DIR`、`REMOTE_HAND_CLAUDE_LOCAL_ROOT`、`REMOTE_HAND_CLAUDE_MANAGED_ROOT`、`REMOTE_HAND_SHIM_BIN`。
  - 推送与通知：`REMOTE_HAND_PUSH_CONTACT`、`RH_PUSH_ALLOW_INSECURE_ENDPOINT`、`RH_NOTIFY_ALLOW_INSECURE_ENDPOINT`。

### 中继的旧环境变量名即将移除

- **中继改名前的环境变量名已弃用，v0.2.135 起不再生效。** 这个版本发出通知：v0.2.134 在新名字没设时中继仍然读旧名字，并且每个旧名字只提示一次它已弃用、v0.2.135 起不再生效。中继由运营者自己运行开源版本，所以请改用同值的 `DROPPEN_RELAY_*` 名字。旧名字是：`RH_RELAY_HUB`、`RH_RELAY_ORIGIN`、`RH_RELAY_KEY`、`RH_RELAY_STATE_DIR`、`RH_RELAY_REGISTRATION_TOKEN`、`RH_RELAY_ID`、`RH_RELAY_TICKET_KEYS`、`RH_RELAY_BIND`、`RH_RELAY_TRUST_PROXY`、`RH_RELAY_MAX_CONNS`、`RH_RELAY_DRAIN_SECS`。（`RH_HUB_API_TRAFFIC` 是所有程序共用的 hub-API 流量捕获名，已列在上面的服务端清单里。）
