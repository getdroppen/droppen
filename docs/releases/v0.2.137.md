## Droppen App for macOS

`Droppen-0.2.137.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.129 to 0.2.136 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to update*. 0.2.133 and 0.2.134 freeze after an update check that finds nothing newer, but not after one that finds this release, so they update the same way; if yours is frozen now, force-quit it (Option-Command-Esc) and open it again: its check about 15 seconds later finds this release. Version 0.2.128 and older are no longer guaranteed to upgrade themselves: install this release once by hand — download this DMG and replace the app in Applications, or run the install script again (`curl -fsSL https://droppen.app/install.sh | sh`) — and later releases update themselves as before.

The server the app runs is now called `droppen-server` (it was `remote-hand-server`), so that is the name Activity Monitor shows. If a firewall or monitoring tool on your Mac has a rule for the old name, add the same rule for the new one.

## macOS 版 Droppen App

`Droppen-0.2.137.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

0.2.129 至 0.2.136 会自动更新到这个版本：在后台下载，并在你下次退出时安装；也可以用「重启以更新」立即安装。0.2.133 和 0.2.134 在检查更新、发现没有新版本后会卡死，但发现这个版本时不会，所以同样会正常更新；如果你的 App 现在已经卡住，请强制退出（Option-Command-Esc）后重新打开：约 15 秒后的那次检查就会找到这个版本。0.2.128 及更早的版本不再保证能自动升级：请手动安装一次这个版本——下载这个 DMG 替换「应用程序」里的 Droppen，或重新运行安装脚本（`curl -fsSL https://droppen.app/install.sh | sh`）——之后的版本会照常自动更新。

App 运行的服务端程序现在叫 `droppen-server`（原来叫 `remote-hand-server`），活动监视器里显示的也是这个名字。如果你的 Mac 上有防火墙或监控软件按旧名字设了规则，请给新名字加上同样的规则。

## What's new in v0.2.137

### Sessions on ACP agents

- **A message an ACP agent does not take now fails, and says why.** If a message asked an ACP agent for another model or effort and then its prompt could not be written — the agent had exited, or had stopped reading — nothing said so: the transcript had no error and the session row still showed the turn before. It now fails: an error in the transcript, the message reads *failed*, and the session's last turn is failed. A write the agent did not read within 30 seconds now says so, instead of saying the agent closed its input.

### Codex

- **A Codex start shows at once.** Starting a Codex session, and giving up on a start, now tell the session list and the open session immediately instead of at their next refresh, so the session no longer keeps showing as idle, or as its last turn, while codex starts.

### The web app

- **A device card's badges move under its name instead of being cut.** On the *my devices* page, a device that both runs AI and is the account's main device showed both badges on the name's line; at some widths the name was truncated and the last badge clipped, in English and Chinese. The badges now wrap under the name when the line cannot hold them, and the name keeps its whole line. Neither the badges nor their wording changed.
- **The offline copy is rebuilt once after the update.** The web app's offline cache has a new name. When it switches, the files this build still lists are carried over from the old cache, each checked against the build's SHA-256, and then the old cache is deleted; a language or a view the page already had offline is not downloaded again. The next online load refreshes the page.
- **Bring it over from the app host finds your device on droppen.app.** On my.droppen.app, *Bring it over* opened the move at the API address instead of droppen.app, where a browser from before the move keeps its device, so the move found nothing to bring over. It now opens droppen.app, and the browser comes over as the same device, without being added again.

### Terminals

- **A long-path terminal's socket lives in a Droppen folder.** A terminal whose socket does not fit in the instance folder now keeps its shim under `/tmp/droppen-<uid>-<tag>` instead of `/tmp/remote-hand-<uid>-<tag>`. Shims left in the old folder are still adopted after a restart, so an upgrade keeps them.
- **A terminal socket served by another local user is refused.** A `/tmp` socket is now dialled only when its folder is a real directory owned by you, with mode `0700`, and the process on the other end runs as you. Otherwise a session that reconnects refuses it, and a terminal whose only socket is untrusted is treated as gone. Rolling back to an older release does not see terminals whose socket is under the new folder.

### The server

- **A custom model price table follows the config folder.** The optional per-model price table now lives at `<config folder>/model-prices.json` — `~/.config/remote-hand/model-prices.json` by default — so `DROPPEN_CONFIG_DIR` moves it with the rest of the configuration. A table at `~/.remote-hand/model-prices.json` is moved there on the next start; if both exist, the new one wins and the old one stays. An older release cannot read the moved table and falls back to the built-in rates.
- **Service logs live under Droppen's own folders.** On macOS the service's logs are now in `~/Library/Logs/Droppen/server/`, and on Linux in `${XDG_STATE_HOME:-~/.local/state}/droppen/`. When the install script runs over an existing install, it copies this instance's logs from the old folder, without moving them and without overwriting a log this release already made, and keeps the old folder. A self-update does not rewrite the service unit, so it keeps writing the old folder until the install script runs again.

### For developers and relay operators

- The protocol, device, devkit and relay library crates are now `droppen-proto`, `droppen-client`, `droppen-devkit` and `droppen-relay-core`.
- The npm workspace packages are `droppen` (the root), `@droppen/web` and `@droppen/e2e`; the plugin SDK was already `@droppen/plugin-sdk`.
- The dev and test environment names are `DROPPEN_*` (`DROPPEN_DEV_PROXY`, `DROPPEN_DEV_PORT`, `DROPPEN_DEV_HUB`, `DROPPEN_CLOUD_DEV_*`, `DROPPEN_FAKE_*`, and so on).
- The relay image builds from `server-rs/crates/droppen-relay-core/Dockerfile`, with the repository root as its build context.
- `cargo build` now produces `droppen-server`; an install still runs `<data>/bin/remote-hand-server`, with `droppen` as its command, and the self-update store, `.prev` and `.bad` keep their paths.
- The web build's view-files token is `__DROPPEN_VIEW_FILES__`.

## v0.2.137 更新内容

### ACP 智能体上的会话

- **ACP 智能体没有接下的消息现在会失败，并说明原因。** 消息要求 ACP 智能体切换模型或推理强度之后，如果提示词写不进去——智能体已经退出，或者已经不再读取输入——不会有任何提示：会话记录里没有错误，会话那一行也仍显示上一轮。现在它会失败：会话记录里有一条错误，消息显示为「失败」，会话的最后一轮也是失败。智能体在 30 秒内没有读取的写入，现在会如实说明，而不再说智能体关闭了输入。

### Codex

- **Codex 会话一开始启动就会显示。** 启动 Codex 会话、以及放弃一次启动时，现在会立即更新会话列表和打开着的会话，而不再等到下一次刷新，所以 codex 启动期间，会话不会再一直显示为空闲或上一轮。

### 网页

- **设备卡片上的标记会移到名字下方，而不是被裁掉。** 在「我的设备」里，既运行 AI 又是账户主设备的设备，会把两个标记和名字放在同一行；在某些宽度下，英文和中文的名字都会被截断，最后一个标记也会被裁掉。现在这一行放不下时，标记会换到名字下方，名字可以使用整行。标记的内容和措辞都没有变。
- **更新后，离线副本会重建一次。** 网页的离线缓存换了新名字。切换时，这一版仍然列出的文件会从旧缓存带过来（每个都按这一版构建的 SHA-256 核对），然后删除旧缓存；页面原来离线就有的语言或视图不会重新下载。下一次在线加载会刷新页面。
- **在 my.droppen.app 上用「迁移过来」，会找到你在 droppen.app 上的设备。** 「迁移过来」以前会在 API 地址打开迁移，而不是在 droppen.app 打开，也就是迁移之前浏览器保存设备的地方，所以迁移找不到可以带过来的东西。现在它会打开 droppen.app，浏览器会作为同一台设备迁移过来，不需要重新添加。

### 终端

- **长路径终端的套接字放在 Droppen 的文件夹里。** 套接字路径放不进实例文件夹的终端，它的 shim 现在位于 `/tmp/droppen-<uid>-<tag>`，而不再是 `/tmp/remote-hand-<uid>-<tag>`。留在旧文件夹里的 shim 在重启后仍会被接管，所以升级不会弄丢它们。
- **由其他本地用户提供服务的终端套接字会被拒绝。** 现在只有满足这些条件才会连接 `/tmp` 下的套接字：文件夹是真实目录（不是符号链接）、属于你、权限恰好是 `0700`，并且对端进程以你的身份运行。否则，重新连接的会话会拒绝它，只有一个不可信套接字的终端会被当作已经消失。回滚到旧版本时，套接字位于新文件夹下的终端不会被识别。

### 服务端

- **自定义模型价格表跟随配置文件夹。** 可选的按模型定价表现在位于 `<配置文件夹>/model-prices.json`（默认是 `~/.config/remote-hand/model-prices.json`），所以 `DROPPEN_CONFIG_DIR` 会把它和其余配置一起移动。`~/.remote-hand/model-prices.json` 里的价格表会在下次启动时移过去；如果两个文件都在，以新的为准，旧的留在原处。旧版本读不到移动后的价格表，会退回内置费率。
- **服务日志放在 Droppen 自己的文件夹下。** 在 macOS 上，服务日志现在位于 `~/Library/Logs/Droppen/server/`；在 Linux 上是 `${XDG_STATE_HOME:-~/.local/state}/droppen/`。在已有安装上重新运行安装脚本时，会把本实例的日志从旧文件夹复制过来，不移动、也不覆盖这一版已经写入的日志，旧文件夹会保留。自更新不会重写服务单元，所以它会继续写旧文件夹，直到再次运行安装脚本。

### 面向开发者和中继运营者

- 协议、设备、devkit 和中继库的 crate 现在叫 `droppen-proto`、`droppen-client`、`droppen-devkit` 和 `droppen-relay-core`。
- npm 工作区的包是 `droppen`（根包）、`@droppen/web` 和 `@droppen/e2e`；插件 SDK 本来就是 `@droppen/plugin-sdk`。
- 开发和测试用的环境变量名是 `DROPPEN_*`（`DROPPEN_DEV_PROXY`、`DROPPEN_DEV_PORT`、`DROPPEN_DEV_HUB`、`DROPPEN_CLOUD_DEV_*`、`DROPPEN_FAKE_*` 等）。
- 中继镜像从 `server-rs/crates/droppen-relay-core/Dockerfile` 构建，构建上下文是仓库根目录。
- `cargo build` 现在生成 `droppen-server`；安装后的服务仍然运行 `<data>/bin/remote-hand-server`，命令是 `droppen`，自更新存储、`.prev` 和 `.bad` 的路径都不变。
- 网页构建的 view-files 标记是 `__DROPPEN_VIEW_FILES__`。
