## Droppen App for macOS

`Droppen-0.2.139.dmg` — the desktop app (Apple silicon and Intel), signed with Developer ID and notarised by Apple. It needs macOS 13 or later. Open the DMG, drag Droppen to Applications, open it.

Droppen 0.2.129 to 0.2.138 update themselves to this release: they download it in the background and install it the next time you quit, or at once with *Restart to update*. 0.2.133 and 0.2.134 freeze after an update check that finds nothing newer, but not after one that finds this release, so they update the same way; if yours is frozen now, force-quit it (Option-Command-Esc) and open it again. Version 0.2.128 and older are not guaranteed to upgrade themselves: install this release once by hand — download this DMG and replace the app in Applications, or run the install script again (`curl -fsSL https://droppen.app/install.sh | sh`) — and later releases update themselves as before.

## Droppen App for Linux

New in this release: the desktop app for Linux, the same app as on the Mac. It starts the Droppen server it carries, signs in for you and shows the web app in its window, so this device is both a device that runs AI and the place you use it from. It needs glibc 2.35 or later (Ubuntu 22.04, Debian 12 and newer), on x86_64 (`x86_64`, `amd64`) or 64-bit Arm (`aarch64`, `arm64`). It comes in two forms:

- **The AppImage**, `Droppen-0.2.139-x86_64.AppImage` or `Droppen-0.2.139-aarch64.AppImage`: one file that carries its own libraries and updates itself. Keep it in a folder you can write to (your home folder, say), make it executable (`chmod +x Droppen-0.2.139-x86_64.AppImage`) and open it. It mounts itself through FUSE (`fusermount3` or `fusermount` on the system; it does not need libfuse2).
- **The .deb**, `droppen_0.2.139_amd64.deb` or `droppen_0.2.139_arm64.deb`, for Debian and Ubuntu: `sudo apt install ./droppen_0.2.139_amd64.deb` installs it with what it needs (WebKitGTK, GTK and the AppIndicator library). Then open Droppen from your app launcher.

The AppImage updates itself as the Mac app does: it downloads the next release's AppImage for its architecture in the background (it waits while NetworkManager says the connection is metered), checks its signature, and writes it over the old file, under the same name, the next time you quit, or at once with *Restart to update*. It does not update where you cannot replace the file (in `/opt`, say: the menu says *Move Droppen to a Folder You Can Write to Update*), nor when it runs unpacked (`--appimage-extract-and-run`). The .deb does not update itself (the menu says *Install a Newer Package to Update*): install the next release's .deb the same way.

Droppen lives in the system tray, so closing the window leaves it running. The tray icon needs a panel that shows StatusNotifier items (on GNOME, the AppIndicator extension); without one, closing the window quits Droppen, and a start at login shows the window. Either way, *Open in Browser* and *Start at Login* are also in Settings → Desktop app. *Start at Login* is on from the first launch (`~/.config/autostart/droppen.desktop`). The password the app signs in to its own server with is kept in the Secret Service (GNOME Keyring, KWallet 5.97 or later, KeePassXC) when the default keyring is unlocked, and otherwise in a file only you can read; the app never asks for the keyring's password. *Open in Browser* opens your default browser signed in, a snap or flatpak one too, without the one-time sign-in on any command line. What the AppImage starts (its server, your sessions and terminals, the browser) gets your desktop's environment, not the AppImage's. Ctrl+R or F5 reloads the window. `Droppen-0.2.139-linux-sources.tar` holds the source of the libraries the AppImages carry and of the AppImage runtime; `LIBRARIES-x86_64.txt` and `LIBRARIES-aarch64.txt` list each library with its Ubuntu package and version.

## macOS 版 Droppen App

`Droppen-0.2.139.dmg` 是桌面 App（Apple 芯片和 Intel 芯片的 Mac 都能用），使用 Developer ID 签名并经过 Apple 公证，需要 macOS 13 或更高版本。打开 DMG，把 Droppen 拖到「应用程序」，然后打开它。

## Linux 版 Droppen App

这个版本首次提供 Linux 版桌面 App，和 Mac 版是同一个 App：它启动自带的 Droppen 服务端，替你登录，并在窗口里显示网页，这台设备因此既是运行 AI 的设备，也是你使用它的地方。需要 glibc 2.35 或更高版本（Ubuntu 22.04、Debian 12 及更新的版本），支持 x86_64（`x86_64`、`amd64`）和 64 位 Arm（`aarch64`、`arm64`）。有两种形式：

- **AppImage**：`Droppen-0.2.139-x86_64.AppImage` 或 `Droppen-0.2.139-aarch64.AppImage`。只有一个文件，自带所需的库，会自动更新。把它放在你可写入的文件夹里（比如你的主目录），设为可执行（`chmod +x Droppen-0.2.139-x86_64.AppImage`），然后打开它。它通过 FUSE 挂载自己（系统里需要有 `fusermount3` 或 `fusermount`；不需要 libfuse2）。
- **.deb**：`droppen_0.2.139_amd64.deb` 或 `droppen_0.2.139_arm64.deb`，适用于 Debian 和 Ubuntu。`sudo apt install ./droppen_0.2.139_amd64.deb` 会把它连同它需要的 WebKitGTK、GTK 和 AppIndicator 库一起装好，然后从应用启动器打开 Droppen。

AppImage 和 Mac 版一样会自动更新：在后台下载新版本里对应架构的 AppImage（NetworkManager 显示当前是按流量计费的连接时会等待），校验签名，并在你下次退出时用它覆盖旧文件，文件名不变；也可以用「重启以更新」立即安装。如果你不能替换这个文件（比如放在 `/opt` 里，菜单会显示「移到你可写入的文件夹后才能更新」），或者它是解开后运行的（`--appimage-extract-and-run`），它不会更新。.deb 不会自动更新（菜单显示「安装新版软件包即可更新」）：请用同样的方法安装新版本的 .deb。

Droppen 常驻在系统托盘里，关掉窗口后它仍在运行。托盘图标需要能显示 StatusNotifier 项目的面板（GNOME 需要 AppIndicator 扩展）；没有的话，关掉窗口就会退出 Droppen，登录时启动也会直接显示窗口。无论有没有托盘，「在浏览器中打开」和「登录时启动」都在「设置 → 桌面 App」里。「登录时启动」从第一次打开起就是开着的（`~/.config/autostart/droppen.desktop`）。App 登录自己服务端用的密码，在默认钥匙环已解锁时保存在 Secret Service 里（GNOME Keyring、KWallet 5.97 或更高版本、KeePassXC），否则保存在一个只有你能读取的文件里；App 从不询问钥匙环的密码。「在浏览器中打开」会以已登录的状态打开你的默认浏览器，snap 或 flatpak 版的浏览器也可以，一次性的登录凭据不会出现在任何命令行里。AppImage 启动的程序（它的服务端、你的会话和终端、浏览器）用的是你桌面的环境，而不是 AppImage 的。按 Ctrl+R 或 F5 刷新窗口。`Droppen-0.2.139-linux-sources.tar` 包含 AppImage 自带的库和 AppImage 运行时的源代码；`LIBRARIES-x86_64.txt` 和 `LIBRARIES-aarch64.txt` 列出每个库对应的 Ubuntu 软件包和版本。

## What's new in v0.2.139

### Codex

- **Codex sessions that went missing after using the Codex app are back.** Newer versions of the Codex desktop app compress a session's file once it has been idle for seven days or more (to `.jsonl.zst`), and Droppen did not read the compressed form, so those sessions dropped out of the session list and could not be opened. Droppen now reads both forms: the sessions are listed and open as before, with their history, search and unread state, and you can send to them again (Codex unpacks the file before it adds to it). Nothing was lost. A session that changes form stays the same session: it is not uploaded again for the offline copy, and its unread state stays as it was.

### Sessions

- **A message keeps the lines you typed.** A message written over several lines (Shift+Enter in the composer, or in the CLI) used to run together into one paragraph in the transcript, since a single line break read as a space. Your own messages now keep each line; a blank line still starts a new paragraph, and code blocks are as they were. Replies are drawn as before. Instant chats already kept the lines.
- **A new session offers only folders you can start in.** The folder list when you start a session no longer offers folders that are gone from the device (a worktree removed after its branch merged, a temporary repository a tool deleted), nor folders under the system's temporary folders (`TMPDIR`, `/tmp`, `/var/tmp`, and `/var/folders` on a Mac), even while they are still there. Their sessions stay in the session list, and a folder you type in or browse to can still be picked. A device on an older release offers every folder, as before.
- **The send shortcut names your keyboard's key.** In Settings, the composer's send shortcut reads *ctrl+enter* instead of *⌘+enter* where the keyboard is not a Mac's.

### The desktop app

- **Settings → Desktop app.** The app's window has a new Settings tab, *Desktop app*, with *Open in Browser* (this device's Droppen page in your browser, signed in, as from the menu-bar menu) and a *Start at Login* switch that shows whether the app really starts at login. When macOS needs you to allow it, the tab says *Allow Droppen in Login Items.* and has *Open Login Items*. The tab is in the app's own window only, not in a browser.
- **The guide says "this device".** The first-run guide and the app's setup page say *this device* where they said *this Mac* (*Droppen is running on this device.*, *Only on this device*), and point at Settings → Desktop app as well as the menu-bar menu.
- **The guide fits a Linux device.** On a Linux device, git's row says to install it with the system's package manager instead of offering Apple's installer, the macOS folder-permission note is not shown, and the PATH hints name your shell's startup file (`~/.bashrc` for Claude Code) instead of `~/.zprofile` and `~/.zshrc`.

### On droppen.app

- **New public pages.** droppen.app's home page is shorter: the download (or sign-up) for your system, with a menu for the others, then a tour of the product, its features, the network, security, the plans, questions and answers, and a last call to action. The download, pricing, security, privacy and terms pages are rebuilt on the same design, and on a narrow screen the security page's contents open in a side sheet. Their text is rewritten in English, simplified and traditional Chinese, and Japanese.
- **New icons.** The web app's icons, on droppen.app, on your device's own page and in the desktop app, are now Phosphor's.
- **The security page says what each address serves.** droppen.app serves an attested release, while my.droppen.app and www.droppen.app are rebuilt from main on every change and can be newer than the latest release: to check them, build the same commit (`docs/web-integrity.md`). Only droppen.app names its build at `/.well-known/droppen-build`.
- **Guangzhou by its name.** The relay picker shows the Guangzhou relay as 广州, 廣州 and 広州 in Chinese and Japanese, instead of *Guangzhou*. droppen.app's pages now connect only to droppen.app's own relays (`*.relay.droppen.app`, and the mainland China relay's address).

### Security fixes

- The server, and the one inside the desktop app, bundle SQLite 3.54.1 (through rusqlite 0.41), which fixes RUSTSEC-2026-0459 (CVE-2026-119375): the SQLite before it could return uninitialised memory when a database was opened with a `-wal` file of another page size.

### For developers and relay operators

- **A relay can move to a new origin.** A relay now tells the Hub its public origin (`DROPPEN_RELAY_ORIGIN`) and its release after every sign-in (`meta`). To move one, make the new origin reach it while the old one still works, set `DROPPEN_RELAY_ORIGIN` to the new one and restart the relay, then drop the old origin once nothing dials it. If the Hub cannot prove the new origin, it keeps the old one and the relay logs a warning (*the Hub kept this relay's old origin*). The version a relay reports is the release (the server's version), not `0.1.0`. `docs/relay.md` and `docs/relay-and-plans.md` §2.5 have the steps.
- The server's API: `GET /api/auth/status` has `platform` (`darwin`, `linux`); `GET /api/sessions/gone-cwds` lists the session folders that are gone; `GET /api/settings` and the feed's `settings` frame have `tempDirs`.
- `scripts/verify-web.mjs` accepts a static host's redirect of `/index.html` to `/` on the same site when `/` serves the attested page, and the web app's `sw.js` is the same file in every build of droppen.app's (it names the canonical hub itself), so my.droppen.app and www.droppen.app can be checked against a build of main as `docs/web-integrity.md` §2 says. A build for another hub (`DROPPEN_WEB_HUB_ORIGIN`) still works; its `sw.js` differs from the attested one.
- The Linux app is built by `desktop/build-linux.sh`, in Docker and without the network, with tauri-cli and the AppImage tools pinned in `.github/release-tools.lock`. CI builds and smoke-tests it on the pull requests that touch its packaging, and `release.yml` ships it when a release's notes name its four files (`docs/releasing.md`).
- The web app is on `@base-ui/react` 1.x and Phosphor's icons (`@phosphor-icons/react`); pnpm's overrides are in `pnpm-workspace.yaml`.
- The server's tests pass on Rust 1.100, whose cargo moved test binaries: they name the binary a terminal shim runs from (`droppen_pty::testing::shims_run_from`), and `DROPPEN_SHIM_BIN` is gone.

## v0.2.139 更新内容

### Codex

- **使用 Codex App 后从 Droppen 里消失的 Codex 会话回来了。** 较新版本的 Codex 桌面 App 会把闲置七天及以上的会话文件压缩成 `.jsonl.zst`，而 Droppen 以前不读这种压缩格式，所以这些会话从会话列表里消失，也打不开。现在两种格式 Droppen 都能读：这些会话照常列出、照常打开，历史、搜索和未读状态都在，也可以继续给它们发消息（Codex 会在往文件里追加内容之前先把它解压）。没有任何数据丢失。会话在两种格式之间切换时仍是同一个会话：不会为离线副本重新上传，未读状态也保持不变。

### 会话

- **消息保留你输入时的换行。** 分几行写的消息（在输入框里按 Shift+Enter，或在 CLI 里）以前在对话记录里会连成一段，因为单个换行会被当成空格。现在你自己的消息会保留每一行；空一行仍然另起一段，代码块照旧。回复的显示方式不变。即时聊天本来就保留换行。
- **新建会话只列出能开工的目录。** 新建会话时的目录列表不再列出设备上已经不存在的目录（分支合并后删掉的 worktree、工具用完就删的临时仓库），也不再列出系统临时目录（`TMPDIR`、`/tmp`、`/var/tmp`，Mac 上还有 `/var/folders`）下的目录，即使它们还在。这些目录里的会话仍留在会话列表里；你手动输入或浏览到的目录照样可以选。运行旧版本的设备仍会列出所有目录。
- **发送快捷键按你的键盘显示。** 在「设置」里，不是 Mac 键盘时，输入框的发送快捷键显示为 *ctrl+enter*，不再是 *⌘+enter*。

### 桌面 App

- **「设置 → 桌面 App」。** App 窗口的「设置」里新增「桌面 App」一栏，里面有「在浏览器中打开」（以已登录的状态在浏览器中打开这台设备的 Droppen 页面，和菜单栏菜单里的一样），以及一个「登录时启动」开关，显示 App 实际是否会在登录时启动。macOS 需要你允许时，这一栏会显示「在登录项里允许 Droppen。」，并提供「打开登录项」按钮。这一栏只在 App 自己的窗口里，浏览器里没有。
- **引导里说「这台设备」。** 首次使用的引导和 App 的设置页不再说「这台 Mac」，而是说「这台设备」（如「Droppen 已经在这台设备上运行了。」「只在这台设备上用」），并且除了菜单栏菜单，也指向「设置 → 桌面 App」。
- **Linux 设备上的引导说的是 Linux 的做法。** 在 Linux 设备上，git 那一行会让你用系统的包管理器安装，而不是提供 Apple 的安装程序；不再显示 macOS 的文件夹权限提示；PATH 提示写的是你的 shell 启动文件（Claude Code 是 `~/.bashrc`），不再是 `~/.zprofile` 和 `~/.zshrc`。

### droppen.app 上

- **新的公开页面。** droppen.app 的首页更短了：先是适合你系统的下载（或注册），其他系统可以从菜单里选；然后是产品导览、功能、网络、安全、套餐、常见问题和最后的行动号召。下载、价格、安全、隐私和条款页面用同一套设计重做，在窄屏上，安全页面的目录会在侧边面板里打开。这些页面的文字用英文、简体中文、繁体中文和日文重写了。
- **新的图标。** 网页里的图标，无论是在 droppen.app、设备自己的页面还是桌面 App 里，现在都是 Phosphor 的图标。
- **安全页面说明了每个地址提供的是什么。** droppen.app 提供的是经过证明的发布版本；my.droppen.app 和 www.droppen.app 在 main 每次改动后都会重新构建，可能比最新的发布版本更新：要核对它们，请构建同一个提交（`docs/web-integrity.md`）。只有 droppen.app 会在 `/.well-known/droppen-build` 说明自己的构建。
- **广州中继显示中文名。** 中继选择器里，广州中继在简体中文、繁体中文和日文里分别显示为 广州、廣州 和 広州，不再是 *Guangzhou*。droppen.app 的页面现在只连接 droppen.app 自己的中继（`*.relay.droppen.app`，以及中国大陆中继的地址）。

### 安全修复

- 服务端（以及桌面 App 内置的服务端）捆绑的 SQLite 升级到 3.54.1（通过 rusqlite 0.41），修复了 RUSTSEC-2026-0459（CVE-2026-119375）：之前的 SQLite 在打开带有页大小不同的 `-wal` 文件的数据库时，可能返回未初始化的内存。

### 面向开发者和中继运营者

- **中继可以换对外的源了。** 中继现在每次签入后都会把自己对外的源（`DROPPEN_RELAY_ORIGIN`）和发布版本告诉 Hub（`meta`）。换源的步骤：先让新的源能到这个中继，同时旧的源仍然可用；再把 `DROPPEN_RELAY_ORIGIN` 改成新的源并重启中继；没有人再连旧的源之后，再撤掉它。如果 Hub 证明不了新的源，它会保留旧的，中继会在日志里打一条警告（*the Hub kept this relay's old origin*）。中继报告的版本现在是发布版本（服务端的版本），不再是 `0.1.0`。具体步骤见 `docs/relay.md` 和 `docs/relay-and-plans.md` 2.5 节。
- 服务端 API：`GET /api/auth/status` 新增 `platform`（`darwin`、`linux`）；`GET /api/sessions/gone-cwds` 列出已经不存在的会话目录；`GET /api/settings` 和 feed 的 `settings` 帧新增 `tempDirs`。
- `scripts/verify-web.mjs` 接受静态托管把 `/index.html` 重定向到同一站点的 `/`，前提是 `/` 提供的是经过证明的页面；网页的 `sw.js` 在 droppen.app 的每种构建里都是同一个文件（它自己写明了默认的 Hub），所以可以按 `docs/web-integrity.md` 第 2 节的方法，用 main 的构建核对 my.droppen.app 和 www.droppen.app。指向其他 Hub 的构建（`DROPPEN_WEB_HUB_ORIGIN`）照常可用，只是它的 `sw.js` 与经过证明的那份不同。
- Linux 版 App 由 `desktop/build-linux.sh` 在 Docker 里离线构建，tauri-cli 和 AppImage 工具都固定在 `.github/release-tools.lock` 里。改动它打包部分的 pull request 会在 CI 里构建并冒烟测试它；发布说明写出它的四个文件时，`release.yml` 就会发布它（`docs/releasing.md`）。
- 网页改用 `@base-ui/react` 1.x 和 Phosphor 图标（`@phosphor-icons/react`）；pnpm 的 overrides 移到了 `pnpm-workspace.yaml`。
- 服务端的测试在 Rust 1.100 上通过（它的 cargo 改了测试程序的位置）：测试现在明确指定终端 shim 运行的程序（`droppen_pty::testing::shims_run_from`），`DROPPEN_SHIM_BIN` 已移除。
